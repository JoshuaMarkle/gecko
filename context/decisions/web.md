# Decisions: Web UI

The web app: views, interaction, local data and visual design. Newest last. Format: date — decision — why.

- 2026-10-20 — Web visual design adapted from the user's JAGUAR design doc into `context/design.md` (monochrome, one accent, semantic colors for state only, dense tool shell). — Requested; keeps both projects' tools consistent.
- 2026-10-20 — SSE terminal events are `done` / `failed` (not `error`). — `error` collides with EventSource's built-in connection error event.
- 2026-10-20 — Web toolbar modeled on the Unity editor: icon view tabs (Home, Results, Layout analysis) left, Play / Pause / End centred, progress right; wordmark removed; Algorithm moved into Inputs › Search. — Requested by the user.
- 2026-10-20 — Transport active state uses `--accent` (Unity's blue play-mode tint) instead of ink. — The live run is "the one thing that needs attention"; keeps the one-accent rule.
- 2026-10-20 — Atlas statistics run in WASM (`AtlasView`), not on the server. — Re-weighting, brushing and re-ranking 10⁴–10⁵ optima must be instant; the binary files load directly.
- 2026-10-20 — The PCA map is fit on ≤ 3000 strided rows and does not depend on weights. — Points keep their place while weights change; only colour and rank move.
- 2026-10-20 — Card grids use `grid-template-columns: minmax(0, 1fr)`. — An `auto` track grew to the canvas's initial 600px width and the size observer then kept it there (charts overflowed their cards).
- 2026-10-20 — Finger palette is vivid, not muted (supersedes "keep desaturated"). — User asked for stronger finger colors; hues stay lighter than the accent so selection edges remain visible.
- 2026-10-21 — Navbar (#82): inputs are top-level tabs in two toolbar tracks (Board · Hand · Corpus · Profile · Search | Optimize · Explore · Stats · Runs); the start layout, editor, pins and reference stay on Optimize's left panel rather than a tab of their own. — The layout is edited on the 3D view, so it belongs beside it; the issue's tab list has no Layout tab. Input state is one hook (`web/src/inputs.ts`) owned by App and passed down as props, not a context — one owner, no extra dependency. Hand is a placeholder until the hand module (#33/#92). Stored `gecko.view` values from the old shell map to the new tabs.
- 2026-10-21 — Frontend redesign built from `frontend.md`: Optimize removed (Home replaces it; the layout editor moved to Search as a 2D click-to-swap overlay with Pin mode). — Requested; views first, features behind them later.
- 2026-10-21 — Working model = the layout adopted from a finished run, a picked saved layout or an Explore pick (`gecko.model`); editing the loaded layout keeps the model but Home then labels the edited layout. — Spec: "the layout currently selected after an optimization".
- 2026-10-21 — Custom boards (key edits on the Board tab) live in browser storage and score in WASM only; Play refuses them. — No geometry write/upload route yet; never modify bundled boards.
- 2026-10-21 — Local languages: sources in IndexedDB, Summarize builds the `.gkc` in WASM (`corpus_from_text`, default charset) for stats only; they cannot be used for runs yet. Bundled corpora are read-only and always Summarized. — Real language stats without new server write routes; upload route planned.
- 2026-10-21 — Corpus sources served read-only from `data/corpora/src/<name>/` (loose files in `src/` belong to `english`). — The Gutenberg texts already lived there; no data moved.
- 2026-10-21 — Hand tab: average adult hand from rounded published phalanx/palm measurements, presets ×0.92 / ×1.08, a synthetic population (overall scale sd 5.5% × shape noise 4%) for size and similarity until reference data lands; planar finger IK with coupled PIP/DIP (0.7). — Exploratory; labelled as preview and synthetic in the UI.
- 2026-10-21 — Board goodness, chance of optimal and time to optimum are heuristics: geometry-only board score (comfort 40, spread 25, thumbs 20, compactness 15); rediscovery rate (hits − 1) / runs over runs on the same board, language and profile; the Gilmore–Lawler gap shown when a run saved one. — Cheap, honest estimators until proper ones exist.
- 2026-10-21 — Stop confidence and board constraints are saved settings with no effect yet. — Spec asks for the views first.
- 2026-10-21 — Hand kinematics: one right-hand skeleton (`handLayout`, mm), the left hand its exact mirror; each hand is placed (wrist + yaw, pulled toward ~10° inward) by a pattern search that fits each finger's natural curl reach to its home key, solved in the right-hand frame so mirrored boards give mirrored hands. The thumb rests on the thumb key nearest its natural rest point (previously the first key in file order, which picked non-mirrored keys). Finger IK searches knuckle flexion and keeps the pose that reaches with joints in limits, closest to DIP ≈ 0.7·PIP. — Symmetric by construction; near keys curl at the knuckle instead of buckling.
- 2026-10-21 — Typing preview: a scheduler (`planTyping`) with Fitts-style move times (0.05 + 0.075·log2(1 + mm/10) s); each press waits for the rhythm, its finger, and the previous release plus (1 − parallel) of its own travel; with parallelism the next finger sets off up to its full travel before the previous release and waits over its key (up to parallel × 0.25 s). The hand follows 30% of finger excursions (thumb 10%). Parallel runs 0–2: above 1 keys roll over (held up to 0.15 s, into the next press) and fingers get ready earlier; a finger cuts its hold short when its own next key needs it, so rollover never slows typing (nor speeds it: same-finger moves are the limit once fingers overlap). Defaults: 40 wpm, 80% parallel. — Shows why overlapping finger motion is needed for speed (serial typing caps near 50 wpm); preview only, not used by the scorer.
- 2026-10-21 — Typing preview keeps the set WPM: keys go down exactly on the rhythm and a finger that cannot make it at its natural pace moves faster (`Press.rush`; a finger needed again lets go of its key early); the natural max (every finger at its natural pace) is reported beside it. Parallel runs 0–3: set-off lead p²·0.25 s and p·max(1, p) travel times before the previous release, home returns only when the finger would rest there; rollover holds no longer gate the next key. Above ~100% speed is limited by same-finger repeats, not overlap. Placement also solves knuckle height and roll (fit each finger's natural drop), and the view adds mirrored wrist offsets (height, distance, spread, angle, tilt, follow) stored in `HandSettings.wrist`. — The user wants the animation at the set speed and a posture playground; rushing is the honest signal for "too fast for these fingers".
- 2026-10-21 — Typing preview back to natural pacing (reverses the strict-WPM entry above for the view): forcing the rhythm made fingers jump unnaturally, so a key waits until its finger arrives at its natural pace and the view shows the speed reached; a longer path (via home) delays the key rather than speeding the move. Strict mode stays in `planTyping` (`strict = true`). — User preference after seeing both.
- 2026-10-21 — Use the shared sidebar width for Explore as well as the input tabs and Home (380px; 340px at ≤1360px) — keep the requested wider left controls consistent across tabs.
- 2026-10-21 — Web "Use hand in optimization" merges the hand into the profile sent to the server/WASM (`withHand`) and adds G01/G05 at the hand profile's weights only when the profile has no weight for them; the stored profile stays hand-free, and auto-added weights are dropped again unless edited. — The toggle must change runs, without silently rewriting a user's explicit weights.
- 2026-10-21 — Export tab: files are built in the browser (`web/src/export.ts`, pure and unit-tested) except the Oxeylyzer / Genkey / cmini formats, which go through WASM `export_layout` so they stay identical to `gecko layouts export`. The image is one standalone SVG string used for both the preview and the download (PNG is that SVG rasterized on a canvas), and KLE uses the flattened 2D drawing rather than raw 3D positions. — No server round trip, so custom boards export too; one drawing means the preview is exactly the file; raw positions of curved boards overlap in KLE (the Dactyl did before the switch).
