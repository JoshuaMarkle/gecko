# Decisions: Search and exploration

Optimizers, runs and their reproducibility, exploration, quality-diversity and bounds. Newest last. Format: date — decision — why.

- 2026-10-20 — Optimizers boxed as `dyn Optimizer` per worker; dispatch is per step (≥ thousands of evals), never per evaluation. — Keeps the runner simple without touching the hot loop.
- 2026-10-20 — SA `steps = 0` means auto: about 4 restarts per worker within the budget. — Fixed 1M-step schedules never finished on short runs with many threads.
- 2026-10-20 — Pause is real: `optimize::Control` (cancel + pause) replaces the bare cancel flag; workers sleep while paused and paused time is excluded from the time budget and `elapsed_ms`. — A UI-only pause would let the budget expire while paused. The deadline check only takes the pause lock once wall time passes the budget, so the hot loop is unchanged.
- 2026-10-20 — Explore hooks into the optimizers through an `Observer` trait object in `Ctx` (`optimum`, `edge`, `exclusions`), called only per descent/kick. — Keeps the dependency direction `explore → optimize`; the hot loop is untouched.
- 2026-10-20 — Atlas stores raw metric vectors per optimum; any profile with the same tables (`Profile::table_hash`) re-ranks it exactly. — "Archive once, re-weight forever" (research/studies/search-space-visualization.md): weight edits never need a new search.
- 2026-10-20 — Mirror canonicalization only when mirrored scores are provably equal and nothing is pinned. — Otherwise mirrored layouts are genuinely different optima; the default ansi profile is not symmetric.
- 2026-10-20 — Exclusion restarts start next to a known good layout and walk out to distance ≥ d, then descend under the Hamming constraint (flagged `CONSTRAINED`). — Random starts rarely land in the band "good but different"; this finds distinct near-best layouts (d = 8, 12).
- 2026-10-20 — BLS stagnation 150 kicks (not 400). — More restarts gave more distinct optima per second with the same best score in 20 s runs.
- 2026-10-20 — Families by leader clustering (radius in slots), not agglomerative clustering. — Linear in the focus size, deterministic, and the radius is meaningful to a user ("≤ 8 keys differ").
- 2026-10-21 — Tabu search keeps a Δ matrix of the *linear* (n-gram) part of every swap delta and adds the finger-load part (M02/M04, non-linear) fresh during each scan. After a move (r, s), pairs touching r or s are recomputed; the others get `Scorer::delta_shift`: Taillard's O(1) QAP update per pair channel plus the trigrams holding a symbol of each pair, found through a new per-symbol-pair trigram index built with the scorer. The matrix and score are rebuilt from scratch every 1000 iterations against f32 drift. — An iteration costs ~3× less than a full rescan with `delta`; exact (proptest) up to f32 rounding. `delta` itself is now `delta_linear + delta_load`, with no measurable speed change (`gecko perf` 1.80 µs before and after).
- 2026-10-21 — Tabu offers a layout to top-K only when the scan shows it is a local optimum (no improving swap), and polishes each restart's best with steepest descent. Tenure is drawn per move (Taillard redraws it periodically); "evals" counts every swap scanned, so tabu's evals/s is not comparable to SA's. — Otherwise top-K fills with one-swap neighbours of the same optimum.
- 2026-10-21 — `gecko verify` refuses time-budget runs, stops before re-running if an input hash differs, and compares scores to 1e-9 relative (chars and evals exactly). — A time-budget re-run can't match by design, and a changed input already explains any mismatch. The tolerance allows last-bit float noise across builds. The re-run writes to a temp dir so the run directory stays as recorded.
- 2026-10-21 — Extra neighbourhoods (same-finger column exchange, 3-cycle, depth-2 swaps) run only at a swap-local optimum inside the shared `steepest_descent`, configured once per run via `Params.moves` (copied onto `Ctx` by the runner), and are off by default. — One switch improves every local search (HC, SA polish, GA, BLS/explore) without touching the hot swap loop; the bench showed no gain for SA/BLS, so swap-only stays the default. Depth 2 tries second swaps only after the 32 least-worsening first swaps (full width is O(m⁴), 60× a swap descent on 30 keys); trial moves restore score/loads from a snapshot rather than subtracting deltas, so no drift.
- 2026-10-21 — MAP-Elites mutation = 2–6 random swaps + steepest descent to a local optimum by default (`qd.descent` 0); a capped descent is opt-in. — In 10 s tests a 3-move cap filled ~40 % more cells but with worse elites (mean +1–2 points) and lost the best layout; full descent keeps every elite a local optimum, comparable with the explore atlas.
- 2026-10-21 — QD axis ranges default to the seed descents' span padded by half on each side; out-of-range values go to edge bins. — Descriptor scales differ per geometry/corpus, so fixed defaults would waste most of the grid; explicit `name:lo:hi` makes runs comparable.
- 2026-10-21 — QD writes elites in the existing `GKATLAS1` record format (`elites.bin`) plus `qd.json`, and reuses `ExploreProgress` (optima = filled cells, hits = offspring) for progress. — Existing readers (re-scoring, WASM) work on elites unchanged; no new progress schema for the web.
- 2026-10-21 — Memetic uses synchronous generations with snapshot ring migration; each island has a stable RNG stream, and worker threads evaluate disjoint island chunks. — Fixed island counts reproduce across worker counts and scheduling; the coordinator alone checks pause/cancel/budgets, avoiding abandoned-barrier deadlocks. Generation work, including child creation and refinement, is counted; budgets may overshoot by one full generation and there is no uncounted final polish.
- 2026-10-21 — Memetic defaults to 24 layouts per island, 12 capped HC moves per child, 2 migrants every 5 generations. HC shares configured larger neighbourhoods; short tabu shares robust tabu's delta matrix and iteration code. Three consecutive generations below one-quarter population trigger fresh random refined children while retaining the elite. — Small populations and bounded duplicate attempts control refinement cost and prevent collapsed populations from spinning indefinitely. SA remains a separate optimizer; the first memetic version exposes HC/tabu refiners.
- 2026-10-21 — Pause regression compares reported elapsed time against measured wall time minus actual paused duration, rather than a fixed 400 ms ceiling. — Parallel builds exposed legitimate optimizer-step overruns (402–461 ms); the test still checks that the full active budget runs and pauses are excluded without assuming scorer throughput.
- 2026-10-21 — Multi-objective Pareto optimization (#21) implements NSGA-II and random-weight SA (RWSA). Uses non-dominated sorting and normalized crowding distance over custom objectives; re-folds existing metric tables for fast delta evaluation without allocation in the hot loop. Persists the non-dominated front in best.json.
- 2026-10-21 — Lower bound (#37): Gilmore–Lawler plus 20 rounds of Hahn–Grant-style dual ascent. Trigrams are relaxed to pair terms by splitting each one into thirds (the minimum over the third key), and load terms are bounded by 0. `best.json` reports both a `total` bound (the certificate) and a `pair` bound (mono + bigram/skipgram part only, as the issue asks). The bound is skipped above 48 movable symbols. — Plain GL is weak on the full board (pair gap 77 %). The ascent is cheap (~0.9 s at 30 symbols) and deterministic. A fixed iteration count keeps runs reproducible. The m⁴ memory caps the size. With pins (few free keys) the bound is tight enough to be useful (1.7 % at 10 free), which is what #43 builds on.
- 2026-10-21 — CMA-ES (#48): own implementation (no crate) with positive weights only, box bounds as a unit-box search plus a squared-distance penalty (the objective never sees out-of-box points), and a batch evaluator API. — Reproducibility needs our RNG on native and WASM; positive-only weights are the textbook variant and enough for ≤ ~50 geometry parameters; batch scoring lets G6 run the inner layout searches of one generation in parallel.
- 2026-10-21 — Holdout (#44): report kept gain = holdout (start − best) ÷ search (start − best) plus Spearman ρ over the top-K, not raw holdout scores alone. — Raw scores differ between corpora (different n-gram mixes), so they are not comparable across corpora; the share of the improvement that survives is, and ρ shows whether the search's ranking of near-equal layouts carries over. The holdout scorer is built from the same start layout, so symbol ids and states transfer without remapping.
