# Decisions: Search and exploration

Optimizers, runs and their reproducibility, exploration, quality-diversity and bounds. Newest last. Format: date — decision — why.

- 2026-10-20 — Optimizers are boxed `dyn Optimizer` per worker, dispatched per step, never per evaluation. — Keeps the runner simple without touching the hot loop.
- 2026-10-20 — SA `steps = 0` means auto (about 4 restarts per worker). — Fixed 1M-step schedules never finished on short runs with many threads.
- 2026-10-20 — Pause is real (`optimize::Control`): paused time doesn't count against the budget. — A UI-only pause would let the budget expire while paused.
- 2026-10-20 — Explore hooks into optimizers through an `Observer` in `Ctx`, called per descent or kick. — Keeps `explore → optimize` and the hot loop untouched.
- 2026-10-20 — The atlas stores raw metric vectors, so any profile with the same `table_hash` re-ranks it exactly. — Archive once, re-weight forever.
- 2026-10-20 — Mirror canonicalization only when mirrored scores are provably equal and nothing is pinned. — Otherwise mirrored layouts are genuinely different optima.
- 2026-10-20 — Exclusion restarts walk out from a known good layout to distance ≥ d, then descend under the constraint. — Random starts rarely land in "good but different".
- 2026-10-20 — BLS stagnation is 150 kicks, not 400. — More distinct optima per second with the same best score.
- 2026-10-20 — Families come from leader clustering by slot radius. — Linear, deterministic, and "≤ 8 keys differ" means something to a user.
- 2026-10-21 — Tabu keeps a Δ matrix of the linear delta (Taillard O(1) updates) and adds load terms fresh; rebuilt every 1000 iterations. — ~3× cheaper iterations; the rebuild bounds f32 drift.
- 2026-10-21 — Tabu offers a layout to top-K only at a local optimum. — Otherwise top-K fills with neighbours of one optimum.
- 2026-10-21 — `gecko verify` refuses time-budget runs, stops on an input-hash mismatch, and compares scores to 1e-9 relative. — Time runs can't reproduce; a changed input already explains a mismatch.
- 2026-10-21 — Extra neighbourhoods (columns, 3-cycle, depth-2) run only at a swap-local optimum and are off by default. — One switch for every local search; the bench showed no gain for SA/BLS.
- 2026-10-21 — MAP-Elites mutation descends fully to a local optimum by default (`descent` 0). — A capped descent filled more cells with worse elites and lost the best layout.
- 2026-10-21 — QD axis ranges default to the seed descents' span, padded by half. — Descriptor scales differ per board and corpus; fixed defaults waste the grid.
- 2026-10-21 — QD writes elites in the `GKATLAS1` format and reuses `ExploreProgress`. — Existing readers and the web work unchanged.
- 2026-10-21 — Memetic runs synchronous generations with stable per-island RNG; only the coordinator checks budgets. — Reproduces across worker counts and avoids barrier deadlocks.
- 2026-10-21 — Memetic restarts with fresh children after three generations below one-quarter population. — Collapsed populations would otherwise spin.
- 2026-10-21 — The pause test compares elapsed time to wall time minus measured pauses, not a fixed ceiling. — Parallel builds showed legitimate step overruns.
- 2026-10-21 — Multi-objective search is NSGA-II plus random-weight SA over re-folded metric tables; the front goes in `best.json`. — Reuses the delta scorer without allocation.
- 2026-10-21 — The lower bound is Gilmore–Lawler plus 20 rounds of dual ascent, skipped above 48 movable symbols. — Plain GL is weak (77% gap); a fixed round count stays reproducible; memory is m⁴.
- 2026-10-21 — CMA-ES is our own implementation (positive weights, box bounds by penalty, batch evaluator). — Our RNG on native and WASM; batches let geometry search run inner searches in parallel.
- 2026-10-21 — Holdout reports kept gain (holdout improvement ÷ search improvement) plus Spearman ρ, not raw scores. — Raw scores aren't comparable across corpora.
- 2026-10-21 — Bilevel geometry search runs a full SA on the start board before CMA-ES; candidates warm-start from the incumbent with one inner seed per generation. — Otherwise early generations measure the layout catching up from QWERTY, not the board.
- 2026-10-21 — Geometry CMA-ES uses σ0 0.1 and IPOP restarts from the best point (`restart_from_best`). — On Corne's touching columns σ0 0.25 and uniform restarts sampled almost only colliding boards.
- 2026-10-21 — A geometry run reports start and best board after equal final SA polishes. — The search phase gives the best board more layout effort; equal polish keeps the gain honest.
- 2026-10-21 — Geometry runs write their own `config.json` (`kind: "geometry"`), not `RunConfig`. — Different parameters and outputs; `verify` dispatches on `kind` (`geomsearch::verify`).
- 2026-10-22 — Geometry collision penalty unit is |start board score| + 1 after the first layout search, not the raw start layout's score. — QWERTY scores ≈ 6× an optimized layout, so the same `--penalty` weighed overlap very differently by start layout.
- 2026-10-22 — Bilevel candidates warm-start from the reported (collision-free-first) board's layout, not the lowest-objective board. — A penalized overlapping board could otherwise steer every later candidate's layout.
- 2026-10-22 — `gecko select` re-scores every gathered layout on one board / corpus / profile instead of reading stored breakdowns or atlas raw vectors. — Runs differ in profile and table hash, and atlases store only their own metric list; one scorer per symbol set keeps 1000 layouts near a second.
- 2026-10-22 — `gecko certify` (B7) is a dependency-free branch and bound (GL + dual-ascent bound, exact leaves), not a HiGHS MIP behind a feature. — An LP linearization of the QAP form certifies only the pair part unless trigrams go cubic; this certifies `Scorer::full` itself, needs no native build, and proves k = 20 in about a minute.
- 2026-10-22 — Certify branches on one free symbol per level (most frequent first) and bounds on the dual-ascent rewrite from the root, computed once. — Re-running ascent per node costs m⁴ per node; the root rewrite already makes every remaining term ≥ 0, so partial costs grow fast.
- 2026-10-22 — `optimize` flags near ties (within 0.4, > 4 keys apart, mirror-invariant) in its output only. — Weight noise moves scores more than that (`bench/sweep-2026-10-22/`); `best.json` stays unchanged so old runs verify.
- 2026-10-22 — `gecko sweep` families use single linkage at 10 keys, mirror-invariant. — Mirrored optima are one arrangement; 10 of 30 keys joins swap variants but keeps apart the optima of σ = 0.5 weight draws (median 21 keys moved).
- 2026-10-23 — Adaptive fidelity (B8) truncates only the trigram list, lives in the runner (not in each optimizer), and moves a worker up a level after `misses` unconfirmed cheap bests by restarting its optimizer from the best confirmed layout. — Pair deltas are dense O(N), so dropping rare bigrams saves nothing; the runner covers hc, sa, ga, bls and tabu without touching their hot loops. Coarse tables are not renormalized: scores stay the full score minus the dropped terms.
- 2026-10-23 — Fingering search (C11) is a best-improvement descent over single-key reassignments after the layout search, each candidate with its own warm-started SA, not a move inside SA. — A reassignment costs a table rebuild (~1 ms, ~1000 swap deltas) and only pays off once the layout adapts; the given fingering gets the same SA so a win is the fingering's, not extra search.
- 2026-10-23 — Phase 2 evaluation (#141) compares each reference only with a search over its own punctuation set, pins corne-36 thumbs to the fills, and drops cmini layouts with blank keys. — Empty keys or a rarer symbol (`;` for `'`) lower the score without a better letter arrangement; the cmini top otherwise is drafts with three blank keys.
- 2026-10-24 — Shift, Ctrl and layer keys are placed by an outer search (each candidate thumb key + steepest descent, then re-anneal) before the layout search, instead of becoming movable. — The scorer's Shift, Ctrl and layer tables depend on them; moving them inside the hot loop would mean rebuilding tables per move.
- 2026-10-25 — `config.json` records a layered start flattened (base then layers), as results are; before, only the base was saved, so layered runs could not `verify`. Runs without layers keep the same config and id. Layered runs of the 2026-10-25 programming and Vim studies had their `start` completed afterwards (`bench/programming-layout-2026-10-25/fix_start.py`) and verify.
