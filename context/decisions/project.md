# Decisions: Project, tooling, tests and docs

Stack, process, CI, testing approach, papers and repository organization. Newest last. Format: date — decision — why.

- 2026-10-20 — Rust core, CLI, server, WASM. — Speed in the hot loop; one scorer shared by CLI and browser.
- 2026-10-20 — TypeScript (not plain JS) for the web UI. — Types help agents work reliably with little supervision; the user is fine with TS for that reason.
- 2026-10-20 — React + react-three-fiber for the UI. — Widely known by agents; good Three.js integration.
- 2026-10-20 — Start with the 30 main keys on a standard row-staggered board. — Requested; symbol layers come later.
- 2026-10-20 — Geometry phases: 2D (x, y, rotation) → z axis + hand model → free-form 3D curved with no key intersections. — Requested roadmap.
- 2026-10-20 — Development is autonomous. Agents make reasonable decisions without asking and record them here. — Requested by the user.
- 2026-10-20 — Own xoshiro256++ RNG instead of `rand`. — Identical streams on native and WASM, no dependency churn.
- 2026-10-20 — Backlog lives in GitHub issues (#1–103, milestones = tracks A–K, native blocked-by links) and project GECKO (#5); `context/roadmap.md` mirrors it as one numbered sequence. No dates: AI development pace makes them meaningless; work goes in order. — Lets agents pick unblocked work unattended; issues carry goal, steps and done-when.
- 2026-10-21 — Overnight harness runs agents in a separate worktree, one PR per issue off main, and skips issues whose blockers are still open (no stacked PRs). — Leaves the user's checkout untouched; dependents get picked up on a later night once their blocker's PR is merged.
- 2026-10-21 — CI: two parallel jobs (rust, web) on stable Rust and Node 24; wasm-pack from `taiki-e/install-action` (prebuilt binary), caches via `Swatinem/rust-cache` and `setup-node`. — Mirrors `make test`; the web job needs its own wasm32 build anyway, and the rustwasm installer script is no longer maintained. No README yet, so no badge.
- 2026-10-21 — Metric unit tests (`tests/metrics.rs`) build boards and corpora in code with explicit n-gram counts (tables summing to 100), not from `data/`, and check each value through both `breakdown` and `Scorer::full` with only that metric weighted. M03 is not implemented, so it has no test. — Hand arithmetic stays readable (counts read as %), tests don't move when data files change, and the folded hot path is pinned to the same hand values as the report.
- 2026-10-21 — Reference snapshots record score plus only the *weighted* metrics per profile, rounded to 4 decimals, one text snapshot per profile. — The diff shows exactly what moves a score while staying readable; 4 decimals absorb f32 summation-order noise (debug and release match). Failing on a mismatch is all CI needs: `cargo test` fails, and CI itself is #1.
- 2026-10-21 — Benchmark history comes from `gecko perf --record` (the CLI's own 0.5 s/1 s timing loops), not from criterion output — criterion's JSON lives in `target/` and changes format between versions; one stable JSONL line per record is easier to diff and plot. Criterion (`cargo bench -p gecko-core`, default features off to avoid plotting deps) is for careful before/after comparisons. Entries are machine-specific; the first entry was recorded on a 20-thread dev machine.
- 2026-10-21 — Issue template is a single `feature.md` mirroring the existing issue body (order/ID/track header, Goal, Steps, Done when, Depends on, Read first); PR template's checklist mirrors the gate commands. — Existing issues #1–103 already use that shape, so agents see one format; no bug template until bugs are filed separately.
- 2026-10-21 — Integrated PRs #125–133 with merge commits, preserving prior main features. Tabu mixed-delta updates include Shift and sparse bracket terms; layer-holder loads use the shared non-linear load path for every load metric. MAP-Elites retains configured neighbourhoods, and corpus extension/adaptive rewriting preserve Shift tables (adaptive context shares are estimates). — Independently developed PRs shared an older base; textual merges alone cannot preserve these interactions.
- 2026-10-21 — WASM/CLI parity (#16) runs the actual browser web-target WASM binary under Node with `initSync` and byte input. Fixtures regenerate from native `compare --json` for all references/profiles; a Rust example serializes Store-resolved geometry/profile inputs. — Tests the shipped binary without a second WASM build target or a JS TOML/defaults implementation; preserves comfort-table inputs and catches per-metric drift as well as total-score drift.
- 2026-10-21 — Embedded web assets (#81) via cargo feature `embed-web` and build-time index of `web/dist`. `gecko serve` serves embedded assets by default when compiled with the feature, or falls back to `<root>/web/dist` with `--web` override. Keeps `/api` routing strictly isolated so API 404s always return JSON errors rather than index.html.
- 2026-10-21 — Claude Code action (#80) triggers only on the repo owner's `@claude` mentions and gets the full Rust/wasm/node toolchain. — Prevents outside users spending the API key; the agent can run the same gate as CI before opening its PR.
- 2026-10-21 — Release/test profiles use `incremental = true` and `codegen-units = 256`; a `max` profile (fat LTO, 1 CGU) holds full optimization. — Build speed matters more than peak scorer speed while in development: a one-line `gecko-core` change rebuilt in ~16 s (release) / ~18 s (tests), now ~1.3 s / ~1.4 s; test-suite runtime unchanged (~26 s). Use `cargo build --profile max` (binary in `target/max/`) for long optimization runs.
- 2026-10-21 — Research paper design studies are dependency-free local HTML with shared CSS and generated SVG figures in `docs/papers/templates`. — Supports webpage-like reading, direct comparison, and browser printing without coupling paper typography to the dense application shell; synthetic examples avoid implying measured results.
- 2026-10-21 — Paper specimens render as white sheets on a neutral desk with page-like margins, using flowing height instead of simulated page breaks. — Gives the requested physical-paper appearance without clipping prose or figures; retains the site's shadow-free design and existing print pagination.
- 2026-10-21 — Retained the two-column journal with more abstract spacing, removed the editorial and notebook specimens, and added a reference-image-inspired research article. — User selected the journal direction and supplied a publication design; blue headings and an article band intentionally extend the app accent convention for this paper only.
- 2026-10-21 — Kept only the journal paper, removed template navigation and title corner labels, removed the abstract divider, and expanded abstract spacing. — User selected the journal as the sole direction; the former comparison URL now forwards to it.
- 2026-10-21 — Added an editable XeLaTeX journal and repeatable PDF build with vector figure assets. — User requested actual PDF export using local LaTeX; the local installation lacks a registered XeLaTeX format and Latin Modern OpenType fonts, so the build initializes a temporary format and the source uses installed Noto Sans without modifying system TeX settings.
- 2026-10-21 — Reorganized `research/`: evidence only (`sources/`, `studies/`, `experiments/`, `archive/`, `OPEN-QUESTIONS.md`); `metrics-catalog.md` and `parameters.md` moved to `context/` (they specify the code); paper templates moved to `docs/papers/templates`; `data-sources.md` merged into `sources/corpora.md`; `hand-model-and-geometry.md` dropped (covered by `context/hand-model.md`, `context/algorithms/geometry-search.md`, `sources/hand-models.md`). Source summaries carry frontmatter and the `sources/README.md` index is generated by `research/scripts/research.py`, which `make test` runs. — The folder mixed evidence, specs, tooling and history, duplicated topics in three places, and had no way to see stale or unverified claims. Rule: research is dated evidence, `context/` is current decisions.
- 2026-10-21 — Cleanup refactor: CLI split into `cmd/<group>.rs` + `ctx.rs` + `fmt.rs`; `scorer`, `geometry` and `interop` became directories; HandView split into `components/hand/`; run lifecycle in `liveRun.ts`. — Files of 1–3k lines were hard to navigate; public paths kept or updated in one change, CLI output verified byte-identical on 55 commands.
- 2026-10-21 — API types stay hand-written in `web/src/api.ts`, checked by `npm run test:contract` (real server JSON written by a Rust test, `satisfies` against the TS return types) instead of generated with ts-rs. — The TS types are deliberate subsets with UI-friendly unions; generation would add a dependency and derive on ~60 core types, and the check catches renamed or retyped fields, the drift that actually happens.
- 2026-10-21 — The TS hand model stays a port, held equal to Rust by a fixture Rust writes (`web/src/fixtures/hand-parity.json`) rather than calling WASM from the Hand tab. — The tab animates per frame and needs joint positions the scorer never computes; a fixture checks both sides without a WASM round trip.
- 2026-10-21 — `bench/` run copies kept as they are. — Time-budget runs are not reproducible, so they cannot be regenerated; they back the leaderboards in `context/algorithms/`.
- 2026-10-21 — `CLAUDE.md` is just `@AGENTS.md`; `context/README.md` is a file index; `decisions.md` and `web.md` split by area. — Three routing tables and two instruction files had drifted apart; one source each.
