# Decisions: Scoring, corpora and layouts

Metrics, profiles, the scorer, corpora, layouts, layers and adaptive keys. Newest last. Format: date — decision — why.

- 2026-10-20 — Linear metrics folded into one table per n-gram order; delta evaluation for swaps. — Metric count doesn't slow search.
- 2026-10-20 — Profile weights apply to metric values in natural units (%, avg effort); direction comes from the metric so weights are always ≥ 0. Spread-normalization deferred. — Simple and readable; default weights tuned so the ranking test passes.
- 2026-10-20 — Frequencies normalized over the symbols on the layout. — Layouts with different punctuation stay comparable; matches common analyzers.
- 2026-10-20 — Trigrams stored sparsely per symbol with `trigram_coverage` = 0.99 (renormalized) in the profile. — ~2× faster deltas; scoring, deltas and reports use the same table so delta == full holds.
- 2026-10-20 — Metric tables grouped in `metrics/mod.rs` (+ `trigram.rs`) instead of one file per metric. — Most metrics are 1–3 lines; one file each would be noise. Split when a metric grows.
- 2026-10-20 — Bundled corpus: 10 public-domain Project Gutenberg novels (6.1M chars); compiled `data/corpora/english.gkc` is committed, raw text is not. — Works offline; reproduces published QWERTY SFB (6.63% vs ≈ 6.6%). Add chat/code corpora later.
- 2026-10-20 — Community corpora imported from cmini's `words.json`, not its n-gram tables; skipgrams across word boundaries estimated by word independence. — cmini's tables have no cross-word n-grams, but GECKO's skipgrams span spaces; word counts make in-word counts exact and let us estimate the rest. QWERTY SFB matches the source tables exactly (shai 6.70 %).
- 2026-10-20 — Corpus format `GKCORP2` adds skip-2 and skip-3 tables (for decayed skipgram metrics); `GKCORP1` still loads with them zero. — Old files keep working; `english.gkc` rebuilt (scores unchanged).
- 2026-10-20 — Robustness report (L05) ranks layouts per corpus and sorts by mean rank, not by raw score spread. — Corpora differ in overall difficulty, so raw scores aren't comparable across them; ranks are.
- 2026-10-20 — Profiles carry `[sfb]` params (distance transform, lateral, finger factors, skip decay); metric tables are built per profile. — Same-finger cost shape is a modelling choice, not geometry. Defaults reproduce the old B03.
- 2026-10-20 — Far skipgrams (gaps 2–3) are a third pair channel (`fkf`/`ckf`) used by S02, not mixed into S01. — S01 stays comparable with other analyzers; the channel is compiled out when unused.
- 2026-10-20 — B14 ported from Oxeylyzer 2 (`cached_layout.rs` @52b271a), constants unchanged. — One stretch formula for every geometry; replaces hand-listed LSB/scissor flags in the default profile at their combined spread weight.
- 2026-10-21 — S04 is one metric, the B14 stretch table on the gap-1 skipgram channel; no separate skip-LSB/skip-scissor flags. — B14 already covers LSB, scissors and crossings, and replaced B04/B05 in the default profile. Weight 0.19 spread units = B14's per-unit weight × S01/B01 (0.12, Oxeylyzer's skip ratio), since no reference tool gives a better number; Kühlmak only says "lower than direct". Colemak-DH now ranks ahead of Dvorak (29.79 vs 29.99): Dvorak's skip stretch is high (11.0).
- 2026-10-20 — Comfort tables live in `data/comfort/`, named per metric by the geometry (`[comfort]`), and are serialized with it. — They are tied to key positions; serializing them keeps WASM == CLI without a new API.
- 2026-10-20 — E05 (measured Engram comfort) in the default profile at weight 1 (spread units). — Without it the optimum was last of all layouts on measured comfort; with it the optimizer gives up 0.2% of the rest of the objective and beats every reference layout on comfort.
- 2026-10-20 — Default profile in spread units (`[scale]` = stdev over the 10 reference layouts). — Weights become comparable; it showed SFB carries ~8× any other metric.
- 2026-10-20 — Ranking test no longer orders Colemak vs Dvorak; it pins modern < {Colemak-DH, Dvorak} < QWERTY. — With B14 and E05 the default profile puts Dvorak level with Colemak-DH (28.9 vs 29.2); the measured comfort data favours Dvorak's alternation. Revisit if this is judged wrong.
- 2026-10-20 — `Analysis` carries every bigram and skipgram with a `kind` (first match of SFB/LSB/scissor, or SFS for skipgrams; else same-hand/alternate). Same-hand and alternate arcs start hidden in the UI (they swamp the view). — The n-gram overlay draws all pairs, not just the worst; classing in core keeps it consistent with the metric tables. Overlaps (e.g. LSB that is also a scissor) count once, under the first kind.
- 2026-10-20 — Special keys are chars with reserved glyphs (`␣ ⏎ ⌫ ⇥ ⎋`, `·` empty), not a `Symbol` enum; text input also takes `{space}`-style names. — Keeps every char-string path (runs, atlas, WASM, web) working unchanged; one char per slot keeps rows and swaps trivial. Revisit if layers need richer symbols.
- 2026-10-20 — `␣` joins the default charset; bundled corpora rebuilt (cmini data re-imported). — Thumb boards need space n-grams. 30-key scores are byte-identical because frequencies are normalized over the layout's symbols.
- 2026-10-20 — M02 uses non-thumb loads as shares of non-thumb keystrokes. — Space puts ~18% of keystrokes on a thumb; targets for the 8 fingers sum to 100% and would otherwise be unreachable. Exact old formula when thumbs are idle.
- 2026-10-20 — B05 scissors exclude thumbs; trigrams with a thumb stay "other" (superseded 2026-10-21: T12/T13). — A thumb isn't a finger-row neighbour of the index; thumb-trigram classes need their own metric (M09/T-thumb, later).
- 2026-10-20 — Layers (phase 5) flatten onto a virtual geometry: one slot per (layer, key), minus keys on the finger holding the layer key; `①②③` mark holder keys and never move. — Keeps the hot loop flat and allocation-free; physical metrics see layered symbols at their key; Y01 (layer presses, hold model) and Y02 (code-symbol bigram channel) add the layer costs. MAX_KEYS raised to 128.
- 2026-10-20 — Layered layouts live in `data/layouts/layered/` so `compare` keeps ranking only like-for-like layouts. Bundled `code.gkc` = 1:1:1 mix of Rust (9 crates from the cargo registry), Python 3.14 stdlib top-level modules, TS (hls.js, use-gesture); `--charset code`, newline = ⏎, indentation dropped.
- 2026-10-21 — B11 movement table = KLO `finger_switch_factor` seeds, KLO's finger-length direction rule (factor 2) and row² cost (offset 0.1), plus a lateral term (columns beyond finger spacing, factor 1, KLO ships 0) so it covers LSB. Ring pairs only are scaled by Häger-Ross coupling relative to the six-pair mean. — The KLO table already encodes the other pairs by hand; the independence data is the physical basis for the ring entries the issue asked for. Unbalancing factor left out (no per-key unbalancing in geometry yet, B13).
- 2026-10-21 — B11 in the default profile at 0.5 spread units, on top of B14 (not replacing it). — At 0.5 the reference order is unchanged and the optimum changes by ~0.1% of the objective; at 1 Halmak and Colemak swap places. The two metrics agree at the optimum; B11 adds finger-specific costs (ring coupling, KLO asymmetries) that B14's pure geometry lacks.
- 2026-10-21 — Y04 HRM misfire risk = same-hand, different-finger bigrams starting on a mod key. Rolls into the mod, same-finger pairs and the other hand are free. HRM slots default to non-stretch home keys and can be overridden per key with `hrm`. Not weighted by default. — A mod only misfires while it is held and another key of the same hand goes down. Bilateral-combination configs make same-hand rolls the risky case. A plain bigram table keeps the hot loop unchanged.
- 2026-10-21 — cmini layouts live in one bundle, `data/community/cmini.json` (committed, ~390 KB), not 4000 TOML files in `data/layouts/`; referenced as `cmini:<name>`. Only the 30-key core is imported; layouts with thumb/31st-column letters, missing letters or non-standard fingering are skipped (2156 of 4121, reasons kept in the bundle). Angle-mod layouts keep their written positions and are scored with standard fingering until #47. Duplicates = same core or its left–right mirror; representative = most likes. — Keeps `compare`/`list layouts` on curated references and the repo tidy; the core is what every GECKO 30-key geometry can score, and skipping beats guessing a remap. The correlation report scores unique layouts only so copies don't double-count likes.
- 2026-10-21 — Skipgrams (S01–S03) count any middle token (`x ? z` with `x`, `z` in the charset; space, punctuation or an unknown symbol between all count), over all charset-ended skipgrams. — The finger still travels from `x` to `z` whatever sits between; matches the Layouts Doc definition (same finger with ≥1 key between). cmini's SFS is narrower (its `dsfb-alt` + `dsfb-red` trigram classes: three distinct layout letters, so no space between) and reads lower; compare with T02 and the corpus skip table in mind.
- 2026-10-21 — Trigram classes validated against cmini `table.json` (pinned non-thumb subset in `crates/gecko-core/tests/fixtures/`): all 512 finger triples agree. GECKO keeps cmini's `dsfb-red` inside T06/T07 instead of a separate class, and any trigram with a thumb stays `Other`. — Same-finger redirects are already penalized as redirects and via S01; no profile weights change. Thumb trigram classes are later work.
- 2026-10-21 — Shift (D1, #4) is a fixed `⇧` key on the layout (may repeat, e.g. one per hand), not a corpus token; the corpus keeps case counts as two extra tables (`GKCORP3`: presses before y, presses between x and y; hold model, one press per run of shifted symbols). Costs go to M01 (Shift key effort per press) and Y01 (press, +same-finger extras) via two small own channels; the best `⇧` per shifted key is fixed at build time. No `⇧` = no cost, so existing layouts and scores are unchanged. — A `⇧` token in the n-gram stream would rewrite every letter bigram around capitals and count Shift as SFBs in B01; separate tables keep existing metrics comparable and delta exact.
- 2026-10-21 — Tokenizer folds US-QWERTY shifted characters onto their key when only the key is in the charset (`:` → shifted `;`, `"` → shifted `'`, …), so rebuilt default-charset corpora count `"`/`:`/`?` as keystrokes on their keys; with `--charset code` they stay their own symbols. `GKCORP3` is written only when shift counts exist, so the bundled corpora (no raw sources committed) keep their bytes and hashes; Shift is dormant on them until rebuilt.
- 2026-10-21 — Layer modes (hold, one-shot, toggle) are encoded in the layer-key token (`①` / `⓵` / `❶`), with TOML `mode` as a friendlier spelling that rewrites the token. — Flat strings (runs, `raw:`, WASM, web) stay self-describing with no new field; old runs and layouts are hold as before. One-shot/toggle layers lose only the layer key (the finger is free); a toggle layer's own key position is where it is left. Y01 counts the presses between two symbols per mode (toggle state = the first symbol's layer), and Y02 also flags pairs after a one-shot symbol.
- 2026-10-21 — Asymmetric row costs (C3) are a profile table `row_offset` added to M01 effort, not new geometry efforts. Default/code: ring ∓0.1, middle ∓0.2, index ±0.2 (above/below home), pinky 0; zero when absent, and left out of `table_hash` then. — Works on every geometry and stays tunable/calibratable; values scaled from KLO's crkbd key costs (≈7.5 KLO units per effort unit). Reference ranking unchanged on ansi-30; M01 `scale` not re-normalized (shift is <2%).
- 2026-10-21 — Chat and non-English corpora for L05: cmini `reddit` (chat) and `french` (picked over `dutch`: larger user base, many accented letters to exercise folding). French is imported with opt-in `--fold` (Latin diacritics/ligatures → ASCII base letters, cp1252 ``/`` repaired). — The default charset is ASCII, so unfolded `é` (2 % of French letters) would break n-grams; folding models typing it as its base key plus a dead key. Opt-in keeps existing corpora byte-identical on rebuild (checked: shai). On French, Canary ranks 1st and Semimak drops to 4th (L05 spread 3).
- 2026-10-21 — C4 metrics (#17) ship unweighted in every profile. — They report now and are ready for `gecko profile fit`/normalize; adding weights would shift the calibrated ranking and belongs to a deliberate re-tune.
- 2026-10-21 — M03 = √Σ share² and M07 = max share ÷ `finger_target`, both over non-thumb shares like M02; scored linearly in the reported value (so explore re-scoring needs no special case). — RSS needs no target (Kühlmak); M07 reuses the existing targets so "pinky especially" falls out of the low pinky target instead of a new profile field. M07 is a max (non-smooth) but exact in the delta since load terms are recomputed from the accumulators.
- 2026-10-21 — B07 = inward bigram rolls only (one ID, Max); B09 = pinky–ring pairs only; B06 uses finger length order pinky < index < ring < middle; S05 uses B14 stretch as KLO's "movement cost" (works on any geometry, unlike the E05 comfort table); T09 = sum of both B14 stretches when both steps stretch; T10 = both bigrams "bad" (SFB, LSB, full or half scissor). — Simplest readings of the catalog that need no new profile parameters; thumbs are excluded from the row/finger-pair metrics as in B05.
- 2026-10-21 — Layout import (Oxeylyzer/genkey/cmini) maps keys by physical position onto the 30 alpha keys and ignores source fingering (angle mod) with a warning; a letter outside those keys (thumb, extra column) is an error, other dropped symbols a warning. ISO bottom rows with 11 keys drop the ISO key (traditional) or the key at B's position (angle) — matches the reference Sturdy. — GECKO geometries carry the fingers; no angle-mod board exists yet. Silently dropping a letter would score a layout without it.
- 2026-10-21 — Y03 paired symbols: a sparse per-pair list weighted by open+close symbol frequency (not bigram frequency, since `(` and `)` are rarely typed back to back), cost 0 for adjacent/mirrored on one layer with the opener left / on the left hand, 50 reversed, 100 otherwise; "mirrored" = same row, finger and stretch flag (not exact column). `code` profile weight 0.5, scale 25 (one typical pair's share). — Keeps the delta to ≤ 4 entries; order matters for memorability but less than proximity; finger+row matching works on any geometry without a mirror map.
- 2026-10-21 — Word counts live in a side file `<corpus>.words.tsv`, not in the `.gkc`. — Keeps the corpus format and hashes (recorded in every run) unchanged; only word imports have word counts. Capped at the 20 000 most frequent words (shai: 246 KB): the tail never reaches a frequency × cost top list.
- 2026-10-21 — No word list for `mt-450k` (or text-built `english`/`code`). — mt-450k weights all 450k words once, so a 20k cap would be an arbitrary alphabetical slice and the full list is ~5 MB; `english`'s source novels aren't in the repo. `analyze --words` errors clearly instead; `shai` and `mt-10k` cover the use case.
- 2026-10-21 — Worst words cover lower-is-better metrics only; costs are per occurrence (% tables ÷ 100, so SFB cost = number of SFBs), ranked by freq × cost; cross-word n-grams belong to no word. — "Worst" for a higher-is-better metric (rolls, alternation) has no per-word cost to blame; per-occurrence counts read naturally (`decided`: 4 SFBs on QWERTY). On a word corpus without `␣` the words' SFBs sum exactly to B01 (tested).
- 2026-10-21 — Thumb trigrams: T12 thumb roll / T13 thumb alternate (T09–T11 were already catalogued). Only thumb-touching steps decide; any same-hand thumb step makes it a roll; same-finger steps (two keys on one thumb) and repeats stay "other". Both `max`, unweighted by default. — Classes still partition all trigrams; the non-thumb step of e.g. `LM LI RT` is already scored by bigram metrics, so it does not split the class further.
- 2026-10-21 — M09 = thumb share %, cost `(share − thumb_target)² / 10` (same form as M04); `thumb_target` default 18 = Space alone on English. Not in `table_hash`: raw M09 doesn't depend on it, so atlases stay re-scorable. — A soft target, not a cap, lets profiles ask for a thumb letter (raise target) or keep thumbs to Space.
- 2026-10-21 — The layer key's own keystroke counts once per layer symbol (chord model) in M01 effort and finger loads (M02/M04), not once per layer entry. — Keeps it a mono term (no bigram table, no extra hot-loop cost beyond a second load index); runs of same-layer symbols are over-counted, but holding still loads the thumb/finger the whole time. Presses per entry stay in Y01.
- 2026-10-21 — Arrow keys are tokens `←↓↑→` (`{left}` …) and their frequencies come from a model, not text: `gecko corpus nav` mixes 3 % arrow keystrokes (runs, mean length 3) into `code` → committed `code-nav.gkc` (3.4 MB). — No keystroke log with cursor movement is available; the model is seeded and documented in `representation.md`, so `code-nav` rebuilds exactly. Arrow↔letter transitions are independent of the letters, so arrow placement results are only indicative.
- 2026-10-21 — Adaptive (magic/repeat) keys are modeled by rewriting the corpus count tables, not raw text, inside `Scorer::new`. — Bundled corpora are counts only (shai is a word list); a rewritten corpus leaves the hot loop, delta and every metric unchanged. Mono/bigrams are exact; trigram and skipgram contexts are Markov estimates (score error ≈ 0.01 vs 3.1 effect on Magic Sturdy).
- 2026-10-21 — Rules key on the previous *output* symbol and are always used when they apply; first listed key wins; no briefs (multi-symbol outputs) or magic-after-magic overrides. — Makes the rewrite a function of the original text (one symbol of context), matching how Magic Sturdy's bigram rules are used; briefs need word-level counts.
- 2026-10-21 — Rules live on `Layout.magic` and in run `config.json`, not in the flat char string. — Keeps every char-string path (runs, atlas, WASM) unchanged; `run:<id>` reattaches them. The web UI does not show or edit rules yet.
- 2026-10-21 — `gecko magic` searches rules by lazy greedy over all on-layout pairs with exact re-scoring, plus a prune pass; `--min-gain 0.01` default. — Top-follower candidate lists missed the key rules (`eu`, `ao` are rare followers but costly SFBs); exact scoring is ≈2 ms per candidate, ~750 evals per search.
- 2026-10-21 — Cache each current unweighted f32 trigram cost in `State`, addressed by stable sparse-entry IDs; `apply` refreshes only affected entries, including trial-move undo. — Removes the old-layout table lookup without changing frequency/difference rounding or allocating in the hot loop. Inline entries with IDs beat the baseline by 16.3% in alternating pinned-core samples; CSR indirection into shared entries was slower and rejected. Frequency premultiplication is not layout-independent and weighted caches alter rounding.
- 2026-10-21 — Fit community likes with nonnegative pairwise logistic loss and L2=0.01; use one representative per duplicate/mirror group, exclude zero-like layouts and tied labels, and hold out 20% of whole layouts before scales/pairs are built. — Prevents pair leakage and treating fame counts as precise comfort labels. Engram stays an independent baseline; the existing E05 judge-fit remains available. Save the learned model as opt-in `learned`, leaving defaults intact because held-out popularity accuracy is only 53.8%.
- 2026-10-21 — L01/L02 (#41) get a new order, `Order::Place`: a symbol-on-slot table in the scorer (mono-like, two entries per swap delta, folded into the QAP mono matrix), since a per-slot table cannot say which symbol sits there. The QWERTY reference is built in (30 letters fitted to the board) rather than loaded by name, so `Scorer::new` keeps its signature; `familiar_to` accepts only `"qwerty"`. L01 is per shortcut letter (A S Q W half weight; 100 off the left hand, up to 50 by distance from the QWERTY spot, saturating at 2u), L02 is keystroke-weighted (0/50/75/100 by same key/finger/hand/other hand). Both unweighted in existing profiles; new profile `familiar` weights them. — Keeps existing scores and snapshots unchanged and the hot loop allocation-free.
- 2026-10-21 — Web finger capacity is inverse relative typing effort, normalized over the fingers present on the board, with independent lateral / vertical reach costs, mirrored left to right by default; optional in core profiles. — Higher cost consistently means harder; including thumbs avoids reserving capacity for absent fingers; optional keeps legacy runs and calibration. Defaults are heuristics, independent of hand mechanics.
