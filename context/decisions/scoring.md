# Decisions: Scoring, corpora and layouts

Metrics, profiles, the scorer, corpora, layouts, layers and adaptive keys. Newest last. Format: date — decision — why.

- 2026-10-20 — Linear metrics fold into one table per n-gram order; swaps use delta evaluation. — Adding metrics doesn't slow search.
- 2026-10-20 — Weights apply to metric values; direction comes from the metric, so weights are always ≥ 0. — Simple and readable.
- 2026-10-20 — Frequencies are normalized over the symbols on the layout. — Layouts with different punctuation stay comparable; matches common analyzers.
- 2026-10-20 — Trigrams are stored sparsely per symbol, `trigram_coverage` 0.99 (renormalized). — ~2× faster deltas; one table for score, delta and report keeps delta == full.
- 2026-10-20 — `english.gkc` (10 Gutenberg novels, 6.1M chars) is committed; its raw text is not. — Works offline; reproduces published QWERTY SFB (6.63% vs ≈ 6.6%).
- 2026-10-20 — cmini corpora come from `words.json`, not its n-gram tables; cross-word skipgrams are estimated by word independence. — cmini's tables lack the cross-word n-grams GECKO's skipgrams need; QWERTY SFB still matches exactly (shai 6.70%).
- 2026-10-20 — L05 ranks layouts per corpus and sorts by mean rank, not raw score spread. — Corpora differ in difficulty; ranks compare across them, raw scores don't.
- 2026-10-20 — Same-finger cost shape (`[sfb]`) is a profile parameter, not geometry. — It is a modelling choice; defaults reproduce the old B03.
- 2026-10-20 — Far skipgrams (gaps 2–3) are their own channel for S02, not mixed into S01. — S01 stays comparable with other analyzers.
- 2026-10-20 — B14 is ported from Oxeylyzer 2 (`cached_layout.rs` @52b271a) with constants unchanged, replacing hand-listed LSB/scissor flags. — One stretch formula for every geometry.
- 2026-10-21 — S04 = B14 stretch on gap-1 skipgrams, weight 0.19 spread units (B14's weight × Oxeylyzer's 0.12 skip ratio). — B14 already covers LSB and scissors; no tool gives a better ratio.
- 2026-10-20 — Comfort tables (`data/comfort/`) are named by the geometry and serialized with it. — They are tied to key positions; serializing keeps WASM == CLI with no new API.
- 2026-10-20 — E05 (measured Engram comfort) is in the default profile at weight 1. — Without it the optimum ranked last on measured comfort; adding it costs 0.2% of the rest of the objective.
- 2026-10-20 — The default profile uses spread units (`[scale]` = stdev over the 10 reference layouts). — Weights become comparable; it showed SFB carried ~8× any other metric.
- 2026-10-20 — The ranking test pins modern < {Colemak-DH, Dvorak} < QWERTY, not Colemak vs Dvorak. — With B14 and E05 the two are level. Revisit if judged wrong.
- 2026-10-20 — `Analysis` gives every pair one `kind` (first match), classed in core. — The overlay stays consistent with the metric tables; overlaps count once.
- 2026-10-20 — Special keys are reserved glyph chars (`␣ ⏎ ⌫ ⇥ ⎋`, `·` empty), not a `Symbol` enum. — Every char-string path (runs, atlas, WASM, web) keeps working; one char per slot keeps swaps trivial.
- 2026-10-20 — M02 measures non-thumb loads as shares of non-thumb keystrokes. — Space puts ~18% on a thumb, which would make the 8-finger targets unreachable.
- 2026-10-20 — Layers flatten onto a virtual geometry, one slot per (layer, key); holder keys `①②③` never move. — Keeps the hot loop flat and allocation-free; Y01/Y02 add the layer costs.
- 2026-10-20 — Layered layouts live in `data/layouts/layered/`. — `compare` keeps ranking like-for-like layouts only.
- 2026-10-21 — B11 = KLO's `finger_switch_factor` table plus a lateral term; Häger-Ross coupling scales ring pairs only. — KLO already encodes the other pairs; the coupling data is the physical basis for ring.
- 2026-10-21 — B11 weighs 0.5 spread units, on top of B14 (superseded 2026-10-22: 0.25 in the retune). — At 0.5 the reference order is unchanged; at 1 Halmak and Colemak swap.
- 2026-10-21 — Y04 HRM misfire = same-hand, different-finger bigrams starting on a mod key; unweighted. — A mod misfires only while held and another same-hand key goes down.
- 2026-10-21 — cmini layouts live in one bundle (`cmini:<name>`), 30-key core only; layouts that don't map are skipped with the reason kept. — Keeps references curated and the repo tidy; skipping beats guessing a remap.
- 2026-10-21 — Skipgrams (S01–S03) count any middle token, space included. — The finger still travels from `x` to `z`; cmini's narrower SFS reads lower.
- 2026-10-21 — Trigram classes match cmini `table.json` on all 512 finger triples; `dsfb-red` stays inside redirects. — Same-finger redirects are already penalized as redirects and by S01.
- 2026-10-21 — Shift is a fixed `⇧` key with its own count tables (`GKCORP3`), not a corpus token. — A token would rewrite letter bigrams around capitals and count Shift as SFBs.
- 2026-10-21 — The tokenizer folds US-QWERTY shifted characters onto their key when only the key is in the charset. — Default-charset corpora count `"` and `:` as keystrokes on their keys.
- 2026-10-21 — Layer modes (hold, one-shot, toggle) are encoded in the layer-key token (`①` / `⓵` / `❶`). — Flat strings stay self-describing with no new field.
- 2026-10-21 — Row asymmetry is a profile table (`row_offset`) added to M01, not geometry effort. — Works on every geometry and stays calibratable.
- 2026-10-21 — Accented corpora (French) are imported with opt-in `--fold`. — The default charset is ASCII; opt-in keeps existing corpora byte-identical.
- 2026-10-21 — C4 metrics ship unweighted. — Weighting them belongs to a deliberate re-tune.
- 2026-10-21 — M03 and M07 use non-thumb shares and score linearly; M07 reuses `finger_target`. — No new profile fields; explore re-scoring needs no special case.
- 2026-10-21 — B06/B07/B09/S05/T09/T10 take the simplest reading of the catalog; thumbs are excluded from row and finger-pair metrics (as B05). — No new profile parameters.
- 2026-10-21 — Layout import maps keys by position onto the 30 alpha keys and ignores source fingering; a dropped letter is an error. — Geometries carry the fingers; scoring without a letter would mislead.
- 2026-10-21 — Y03 weights each bracket pair by open + close frequency, not bigram frequency. — `(` and `)` are rarely typed back to back; the delta stays ≤ 4 entries.
- 2026-10-21 — Word counts live in `<corpus>.words.tsv` (top 20k), not the `.gkc`; none for `mt-450k` or text-built corpora. — Keeps the corpus format and run hashes; mt-450k weights every word once, so a cap would be arbitrary.
- 2026-10-21 — Worst words cover lower-is-better metrics only, per-occurrence cost ranked by freq × cost. — Higher-is-better metrics have no per-word cost to blame.
- 2026-10-21 — Thumb trigrams T12/T13: only thumb-touching steps decide the class. — Classes still partition all trigrams.
- 2026-10-21 — M09 thumb share is a soft target and stays out of `table_hash`. — Profiles can ask for a thumb letter; atlases stay re-scorable.
- 2026-10-21 — A layer key's keystroke counts once per layer symbol (chord model) in M01 and loads. — Stays a mono term; holding loads the finger the whole time anyway.
- 2026-10-21 — Arrow-key frequencies are modeled (`gecko corpus nav`, 3%), not taken from text. — No keystroke log with cursor movement exists; arrow placement is only indicative.
- 2026-10-21 — Adaptive (magic) keys rewrite the corpus count tables inside `Scorer::new`. — Corpora are counts only; the hot loop and every metric stay unchanged.
- 2026-10-21 — Magic rules key on the previous output symbol, always apply, first listed wins; no briefs. — The rewrite stays a function of the text with one symbol of context.
- 2026-10-21 — Magic rules live on `Layout.magic` and in run `config.json`, not the char string. — Char-string paths stay unchanged.
- 2026-10-21 — `gecko magic` searches by lazy greedy with exact re-scoring, then prunes. — Top-follower candidate lists missed key rules (`eu`, `ao`).
- 2026-10-21 — Trigram costs are cached in `State` by stable sparse-entry ID. — 16.3% faster; CSR indirection was slower, and premultiplied frequencies change rounding.
- 2026-10-21 — Likes are fit by pairwise logistic loss with one layout per duplicate group and a 20% whole-layout holdout, saved as opt-in `learned` (superseded 2026-10-22: `learned` removed). — Prevents pair leakage; 53.8% held-out accuracy is too low for a default.
- 2026-10-21 — L01/L02 use a new `Order::Place` (symbol-on-slot table); QWERTY is built in; weighted only in `familiar`. — A per-slot table can't say which symbol sits there; existing scores stay unchanged.
- 2026-10-21 — Web finger capacity = inverse relative effort over the fingers on the board; optional in core profiles. — Higher cost always means harder; optional keeps legacy runs and calibration.
- 2026-10-22 — Angle mod is a separate geometry, `ansi-30-angle` (same positions, left bottom row one finger over); a re-fingered key takes its new finger's natural bottom-row effort (ring 2.8, middle 2.4, index 1.8; V = mirrored N, 2.6); `layouts likes` scores cmini angle boards on `<g>-angle`. — Fingering already lives in the geometry; keeping ansi-30's efforts would charge the ring finger for a pinky reach, and derived efforts (G4) run lower than the hand-entered ones beside them.
- 2026-10-23 — Swap-delta trigram loops read slots from a 256-entry table indexed by `u8` (safe code, no `unsafe`); per-symbol cached cost sums rejected. — +7.5% deltas/s with identical results; the cached-cost read is ≤5% of delta time.
- 2026-10-22 — Shift counts ship as a new `english-cased` corpus; `english` stays the frozen default. — 156 runs, including the paper's cited runs, verify against `english`'s hash; rankings of the reference layouts are identical on both.
- 2026-10-22 — Default profile retuned to the timing and comfort evidence (SFB, B14, S01 down; scissors, pinky–ring, row jump, home row, effort, rolls, alternates up; B03 dropped). — Agreement with the time judge on good layouts 0.44 → 0.87 with the reference order kept; keeping SFB at 8.28 gave a worse optimum (`context/objective.md`).
- 2026-10-22 — Bundled scales are stdev over the 9 references without QWERTY. — QWERTY alone set every spread; weights now compare among decent layouts. Same objective (renormalized).
- 2026-10-22 — B03/S03 retired, not deleted: flagged `retired`, still scored, hidden in the UI, skipped by fits. — Timing shows no SFB-distance effect; old runs and profiles must still verify.
- 2026-10-22 — E01 typing time is a fitted bigram table used as a judge (weight 0), not an objective. — Optimizing the judge would remove the independent check on the score.
- 2026-10-22 — E01 uses the 7-feature model (no SFB distance, no roll direction). — Both fit ≈ 0; cross-validated R² 0.669 vs 0.655 with them.
- 2026-10-22 — `learned` profile removed; likes fits print a warning. — Its optimum games the fit (home row 8 %); a likes fit is a ranking aid. Old runs embed their profile.
- 2026-10-22 — B10 measures each key from its finger's home keys (the hand's if none). — Raw y made column stagger along finger length a "jump"; on row-stagger boards values are unchanged.
- 2026-10-22 — The trigram coverage cut keeps its index tie-break. — Ties make scores depend on symbol order by ~3e-5, but changing it would break `gecko verify` of saved runs; tests compare with the run's own symbol order.
- 2026-10-23 — Ranking validation uses community tiers plus likes on 16 named layouts, not likes over all cmini layouts. — No published ranking exists; full-set likes track exposure and memes (ρ +0.08).
- 2026-10-23 — Trigram classes keep first = third trigrams and same-finger-end redirects instead of cmini's `sfR`/`dsfb-red` buckets. — Every trigram gets one class and `ere` is a real redirect motion; the differences are documented in objective.md §Validation.
