# Decisions: Geometry and hand model

Boards (2D, parametric, 3D), KLE import, collision, derived costs and the hand model. Newest last. Format: date — decision — why.

- 2026-10-20 — Geometry / layout / corpus kept separate; positions always 3D. — 2D → 3D without rewriting the core.
- 2026-10-20 — Empty slots (`·`) may repeat and are movable; the optimizer may put a letter on an empty thumb key. — "Unpinned non-alpha slots" by request; `--pin '{none}'` keeps them empty. Empty↔empty swaps are wasted moves (delta 0), accepted.
- 2026-10-20 — Geometry keys get an optional `fill`; `Layout::fit` puts 30-key layouts onto thumb boards. — All reference layouts work on corne-36/sweep-34 without duplicate layout files.
- 2026-10-21 — KLE import guesses rows by aligning same-x columns (then y for loose keys), takes the last of ≥ 4 rows as thumbs, and assigns fingers by nearest home-row column with ties to the left; efforts come from ortho-30's table. Stretch keys are not `home` (ortho/ansi convention; corne/sweep mark them home). — Reproduces all four bundled boards and traditional ANSI fingering from geometry alone; KLE labels vary too much to trust. Imports write no thumb fills: which thumb gets space is a user choice.
- 2026-10-21 — Hand model (#6): Buchholz 1992 kinematic ratios × hand length for phalanges; active ROM (Becker & Thakor 1988) as hard limits, functional ROM (Bain 2015) as the low-cost zone; DIP–PIP as a soft per-finger coupling, not the "⅔" rule. Finger MCP positions come from a scan or geometry parameters, not Buchholz metacarpal ratios. — Phalanx ratios cross-check across two secondary sources; metacarpal ratios and the ⅔ rule could not be sourced, and measured DIP/PIP slopes (0.44–0.87) break down in fingertip-press postures.
- 2026-10-21 — `Geometry::flat2d` (L9): PCA plane per hand only when the halves' plane normals differ by > 5°, otherwise one plane for the board; in-plane axes are board x projected onto the plane (y completes it, pointing toward the user); each half keeps its 3D centroid's x, y. Overlap removal pushes pairs apart along the SAT MTV, signed from center to center, so keys never pass each other (row/column order kept) — no explicit order constraint needed. Served precomputed as `flat` on `/api/geometries` (mini keyboards render before WASM loads). — Keeps a split board's halves where they are and its rows horizontal; flat boards are untouched.
- 2026-10-21 — Imported full Lily58/Kyria/ErgoDox/Dactyl-Manuform 5x6 and replaced Corne/Sweep approximations with pinned QMK-derived KLE projections. Keep all physical slots, leave only the 30 alpha slots unfilled, and add standard thumb fills; other slots fill `none`. — Supports every reference layout without discarding larger boards' auxiliary keys. QMK display coordinates are reproducible, but not measured 3D poses: Dactyl explicitly remains a flat projection; source/limitations live in `data/geometries/sources/README.md`.
- 2026-10-21 — KLE row inference keeps adjacent equal-height (3+ key) columns aligned by ordinal row before considering vertical proximity. — Sweep's sourced 0.62u pinky-to-ring stagger otherwise shifts one column by a row; unequal-height columns still use the existing proximity heuristic.
- 2026-10-21 — Parametric 2D boards (#25) generate standard keys from mirrored zones/rows/columns, with home-pivot column splay, a shared split transform, and circular-arc thumb zones. Compute centers in f64 and cast to f32 once; hashes use resolved geometry content. — About 16 useful shape parameters replace per-key poses, while preserving explicit board metadata and existing scoring/run formats. Corne's exact QMK display projection uses a straight thumb baseline plus one column stagger/height; a circular physical arc is opt-in rather than inferred from display coordinates.
- 2026-10-21 — Store prefers explicit `name.toml` over `name.param.toml`, lists their base name once, and accepts parameter paths/`name.param` explicitly. — Existing CLI/web selections keep their geometry; parameter-only boards are discovered automatically and comfort CSV loading follows the same path.
- 2026-10-21 — 3D boards (#59 groundwork): `Key::rot` means `Rx(rx)·Rz(rz)·Ry(ry)` in board axes, exactly what the viewer already drew (three.js XYZ over `(rx, −rz, ry)`); `gecko_core::pose` holds the math, `CAP_HEIGHT` 0.42 u (the viewer's cap) and the keycap-top contact point. — Keeps every existing file and drawing valid; one convention for core, viewer and hand model.
- 2026-10-21 — Geometric metrics measure between keycap tops in each hand's best-fit plane frame (`Geometry::metric_points`) on non-flat boards, `pos` exactly on flat ones. — Fingertip targets are the keycap tops; a per-hand frame means a rigid tent changes no metric while curvature does (shorter row-to-row travel on a bowl). Flat boards keep bit-identical scores and snapshots. Row/finger-length heuristics (B14's Oxeylyzer offsets) are unchanged and read Dactyl's 12 mm pinky offset as extra stretch.
- 2026-10-21 — Parametric 3D: Dactyl-style `row_curve`/`col_curve` (chord spacing at the keycap tops, so equal spreads lie on a circle), `center_col`, column `lift`, zone and split `tent`/`tilt`/`lift`; a zone without them takes the old flat code path. — Same parameters as the Dactyl generator, so CMA-ES can search them; bit-for-bit compatibility for existing param boards.
- 2026-10-21 — `dactyl-manuform-5x6` is now 3D: poses from `sources/dactyl_manuform.py` (port of the Dactyl-Manuform generator's key placement, default 5x6 parameters), slots/fingers/efforts/fills unchanged; an explicit TOML rather than a `.param.toml` because the thumb fan is six individually posed keys and the bottom row has two columns. — Keeps slot order and saved layouts valid. Reference ranking barely moves (Dvorak/Colemak-DH swap #5/#6); with the hand held still, every alpha key except the outer pinky top is within fingertip reach (Corne misses its top-row pinky/index keys by 3–6 mm).
- 2026-10-21 — Hand model in the scorer (`gecko_core::hand`, #33/#40/#52/#57): a Rust port of the web's skeleton, placement and planar IK with the same constants, producing mono tables G01 (reach: joint deviation from the natural curl, splay over comfortable abduction, fingertip shortfall with the hand planted on the home keys) and G05 (distal phalanx vs keycap normal within the finger plane). — One model for the Hand tab and the scorer; mono tables fold for free, so search speed is unchanged. The press direction is the distal phalanx, not the MCP flexion tangent: the tangent model scored the Dactyl's row tilts as worse, the distal-axis model scores keywells best, as they are designed.
- 2026-10-21 — The hand is measured in each half's best-fit plane frame on 3D boards (`Geometry::hand_frame`, shared with `metric_points`). — Keeps "a rigid tent changes no metric"; tent and pronation belong to a future wrist metric (G03).
- 2026-10-21 — Profile `[hand]` is optional; without it G01/G05 use the average hand and B14 keeps 1.35 u, and bundled profiles other than `hand` weight G01/G05 0. With a hand, B14's relaxed spread scales with span / 200 mm. — Existing profiles, hashes, calibration and snapshots stay unchanged; the hand's size reaches pair costs through the one parameter that measures spread.
- 2026-10-21 — `data/profiles/hand.toml` = default + G01 1.0 + G05 0.5 (spread units) with M01 halved. — M01's hand-entered key efforts already encode reach; halving keeps finger strength without double-counting. On ANSI the hand optimum is 1.9% worse under default while cutting reach 34%.
- 2026-10-21 — The thumb is a 4-DoF chain (CMC flexion + palmar abduction about fixed axes, MCP, IP) solved by damped least squares, in Rust and `hand.ts` alike, replacing the planar finger chain; its rest point moved lower and inward (0.35 × palm length below the knuckles). — The planar chain could not swing sideways, so thumb clusters were costed as reach, not CMC motion; Corne's thumb keys now cost ~0.1–0.2 at rest and Ergodox's far thumb keys show as out of reach, as users report.
- 2026-10-21 — Thumb G05 = asin |key normal · CMC→tip|: only a push along the thumb's line is misaligned. — The CMC's two axes push the tip anywhere across that line. Pressing along palmar abduction alone called the Dactyl's thumb cluster (tilted toward the thumb) 65–75° off; pressing into the pad called every flat thumb key 75–90° off. The line model gives flat ≈ 25°, Dactyl ≈ 12°.
- 2026-10-21 — G03 wrist posture (#63) works in board space while G01/G05 stay in each hand's frame: the hand's axes are turned back through `Frame::undir`, so tents show as lower pronation. The elbow sits `elbow_width / 2` from the board's middle, level with the wrist; default `elbow_width` 465 mm is calibrated so flat boards give the ≈ 12° conventional-keyboard ulnar deviation (ANSI 12–13°, ortho 12°). — Matches the posture studies (`research/sources/split-keyboard-ergonomics.md`); calibrating to a measured outcome beats guessing a shoulder width the model is very sensitive to (±10 mm ≈ ±1.3°).
- 2026-10-21 — G03 treats a board with ≥ 1 u between the hands' finger keys as split and assumes each half is turned to line up with the forearm (no resting deviation). — Split geometries come from QMK display coordinates with "illustrative split spacing"; scoring that drawn spacing would penalise splits for a gap nobody types at.
- 2026-10-21 — G03 is weighted 1.0 in natural units (no scale) in `hand.toml` and the web's auto-added weights. — Its spread over layouts on one board is ~0.004 (only sideways misses vary), so spread units would make it a ~250× amplified copy of G01's miss term; in natural units it adds ≈ 1 point between a flat board and a tented split and leaves layout search unchanged.
- 2026-10-21 — Geometry rebuild (#32): `Scorer::set_geometry` updates tables in place and refolds only touched entries in `new`'s order, rather than folding deltas (`c += w·(new − old)`). — Bit-identical to a fresh build, so runs stay reproducible whether a scorer was built or rebuilt; incremental deltas would drift in f32. Pose-only moves skip the logical tables via a second mask; which tables read metric points is one list (`metrics::reads_points`), guarded by the rebuild test.
- 2026-10-21 — Collision (#39): `Geometry::validate` rejects overlapping keycaps (margin 0); a separate `check_keys` keeps the structural checks for layer expansion and `Scorer::set_geometry`. 2D only, flat boards only. — Hand-written and imported boards must be physical, but search candidates that collide must stay scorable so a geometry search can penalize depth instead of failing; projecting tilted 3D keycaps to 2D would flag keys that clear each other in height, so 3D waits for H8.
- 2026-10-21 — Derived costs (#42): missing `effort` is a NaN sentinel resolved on load (`from_toml`, parametric `generate`), and `check_keys` rejects any non-finite effort; derived stretch applies only when a board file marks no key `stretch`. Effort is linear in distance to the finger's home key with per-finger fitted slopes; stretch is a 0.625 u inward offset of the index. — Keeps `Key` and every consumer (scorer, web, KLE) on plain numbers; the sentinel never leaves the loader. A `stretch` field cannot be told apart from `false` after serde, so its absence is read from the raw TOML. Linear fits the bundled efforts as well as quadratic; the hand model (G01) is the long-term effort source.
