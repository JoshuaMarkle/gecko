# Decisions: Geometry and hand model

Boards (2D, parametric, 3D), KLE import, collision, derived costs and the hand model. Newest last. Format: date — decision — why.

- 2026-10-20 — Geometry, layout and corpus are separate; positions are always 3D. — 2D → 3D without rewriting the core.
- 2026-10-20 — Empty slots (`·`) may repeat and are movable. — Lets the optimizer put a letter on a spare thumb key; `--pin '{none}'` keeps them empty.
- 2026-10-20 — Geometry keys have an optional `fill`; `Layout::fit` puts 30-key layouts onto bigger boards. — Every reference layout works on every board without extra layout files.
- 2026-10-21 — KLE import infers rows, thumbs and fingers from positions, not labels; it writes no thumb fills. — KLE labels vary too much to trust; which thumb gets space is the user's call.
- 2026-10-21 — KLE row inference aligns adjacent equal-height columns by ordinal row first. — Sweep's 0.62u pinky stagger otherwise shifts a column by a row.
- 2026-10-21 — Hand proportions: Buchholz 1992 phalanx ratios, Becker & Thakor active ROM as limits, Bain 2015 functional ROM as the low-cost zone; DIP–PIP is a soft coupling. — The metacarpal ratios and the "⅔" rule could not be sourced.
- 2026-10-21 — `flat2d` uses one plane per hand only when the halves differ by > 5°; overlaps are pushed apart along the SAT MTV. — Split halves stay put and rows horizontal; keys never pass each other.
- 2026-10-21 — Lily58, Kyria, ErgoDox, Dactyl and Corne/Sweep come from pinned QMK-derived KLE projections, keeping every physical slot. — Reproducible sources; limits in `data/geometries/sources/README.md`.
- 2026-10-21 — Parametric boards are mirrored zones/rows/columns, computed in f64 and cast once; hashes use resolved content. — ~16 parameters replace per-key poses and keep run formats.
- 2026-10-21 — The store prefers `name.toml` over `name.param.toml`. — Existing selections keep their geometry.
- 2026-10-21 — `Key::rot` means `Rx·Rz·Ry` in board axes, as the viewer already drew it. — Every existing file stays valid; one convention for core, viewer and hand.
- 2026-10-21 — Geometric metrics measure between keycap tops in each hand's best-fit plane on non-flat boards. — A rigid tent changes no metric while curvature does; flat boards stay bit-identical.
- 2026-10-21 — Parametric 3D uses the Dactyl generator's parameters (`row_curve`, `col_curve`, tent, tilt, lift). — CMA-ES can search them; flat zones keep the old code path.
- 2026-10-21 — `dactyl-manuform-5x6` is an explicit 3D TOML from the generator, not a `.param.toml`. — Its thumb fan is six individually posed keys; slot order stays valid.
- 2026-10-21 — The scorer's hand model is a Rust port of the web's skeleton, placement and IK (G01 reach, G05 press angle). — One model for tab and scorer; mono tables fold for free.
- 2026-10-21 — G05 uses the distal phalanx as the press direction. — The MCP-tangent model scored keywells as worse, the opposite of their design.
- 2026-10-21 — The hand is measured in each half's best-fit plane frame (`Geometry::hand_frame`). — Keeps "a rigid tent changes no metric"; tent belongs to G03.
- 2026-10-21 — Profile `[hand]` is optional; only the `hand` profile weights G01/G05. — Existing profiles, hashes and snapshots stay unchanged.
- 2026-10-21 — `hand.toml` = default + G01 1.0 + G05 0.5 with M01 halved. — M01's key efforts already encode reach; halving avoids double-counting.
- 2026-10-21 — The thumb is a 4-DoF chain solved by damped least squares, in Rust and `hand.ts` alike. — A planar chain can't swing sideways, so thumb clusters were costed as reach.
- 2026-10-21 — Thumb G05 = misalignment with the CMC→tip line only. — The CMC's two axes push the tip anywhere across that line; other models called every thumb key 65–90° off.
- 2026-10-21 — G03 works in board space; default `elbow_width` 465 mm is calibrated to ≈ 12° ulnar deviation on flat boards. — Calibrating to a measured outcome beats guessing a sensitive shoulder width.
- 2026-10-21 — G03 treats ≥ 1 u between the hands as split, with each half aligned to the forearm. — QMK split spacing is illustrative; scoring it would penalize a gap nobody types at.
- 2026-10-21 — G03 weighs 1.0 in natural units, not spread units. — Its spread over layouts is ~0.004; spread units would amplify it ~250×.
- 2026-10-21 — `Scorer::set_geometry` refolds touched entries in build order instead of folding deltas. — Bit-identical to a fresh build, so runs stay reproducible.
- 2026-10-21 — `Geometry::validate` rejects overlapping keycaps; `check_keys` keeps only structural checks; 2D flat boards only. — Search candidates that collide must stay scorable; 3D collision waits for H8. (3D partly superseded: `collisions_3d` below.)
- 2026-10-21 — Missing `effort` is a NaN sentinel resolved on load; derived effort is linear in distance to home. — Every consumer sees plain numbers; linear fits the bundled efforts as well as quadratic.
- 2026-10-21 — `collisions_3d` = SAT on a tapered keycap frustum + MX switch box per key, used by geometry search only. — Exact for convex polytopes without a new crate; `validate` stays 2D until H8 refines the shapes. (Superseded by H8's GJK + EPA below.)
- 2026-10-21 — Geometry search drops hand-entered efforts and derives them per candidate (`--keep-effort` opts out). — Fixed efforts would make M01 blind to moved keys.
- 2026-10-21 — Spread and row pitch default to ≥ 1 u (MX pitch) in geometry search; margin 0. — With 18 mm caps the search packs keys to 18.1 mm pitch, which shortens every distance but fails `validate` and needs Choc-style caps.
- 2026-10-21 — Default bounds: split tent 0–45°, tilt −15–10°, row curve 0–30°. (tilt superseded by the H6 posture prior below.) — The hand model has no finger-vs-keycap clearance term, so the search runs to whatever bound it is given.
- 2026-10-22 — `geomsearch` gains `Mode::Board` (board for a fixed layout), sharing the bilevel CMA-ES loop with the inner layout search off. — The web UI separates "board for this layout" from "board and layout together"; reusing the loop keeps one driver and its pause / progress / run-dir code.
- 2026-10-22 — Posture priors are absolute default bounds (split tilt −4–0°, angle 10–20°, angle joins `--free 3d`); the start board keeps its own values. — Unbounded, the search tilted −12° to −15°, past the measured optimum; the prior is evidence, the start file is not. (Supersedes the tilt −15–10° default above.)
- 2026-10-22 — G07 build limits are a feasibility check folded into the geometry search's collision depth (angles 45° = 1 u, counts 1 key = 1 u), not a scoring metric. — They are hard constraints on the board, not costs on the layout; one penalty and one `hard_fail` keep the search's trade-offs in one unit.
- 2026-10-22 — G07 `max_columns` is off by default; plate pieces are the two hands when their nearest switches are ≥ 1.25 u apart. — Board files label columns loosely (ergodox's right hand has 13 labels); unibody boards have 1 u between hands, bundled splits ≥ 1.5 u.
- 2026-10-22 — H8 keeps the frustum + switch shapes but tests them with GJK + EPA (own code, no crate) and a 3D grid; `validate` now checks 3D on non-flat boards. — EPA gives the separating direction the repair step (I3) needs, GJK takes any hull; SAT stays as the unit-test oracle.
- 2026-10-22 — `Geometry::repair` translates keys only and grows its step 5% per pass. — Rotations are design choices the search owns; three-key jams cycle forever at a fixed half-MTV step.
- 2026-10-22 — The geometry search does not repair candidates; an infeasible run writes `geometry-repaired.toml` beside the parametric best. — A repaired board leaves the parameter space, so `geometry.toml` would no longer equal `geometry.param.toml`; repair belongs in free-form search (I1).
- 2026-10-22 — J4 STL is our own mesh code (incremental convex hull, binary STL), a union of overlapping closed convex shells, not a CSG/boolean library. — No new dependency or C++ build; Dactyl-style hulls are convex anyway, and slicers union overlapping closed shells. Each connector sits a distinct small inset inside the tiles so no shells share vertices (slicers stitch by exact coordinates); verified with Blender's Manifold union.
- 2026-10-22 — J4 drops connectors (webs, junctions, corner walls) that would enter a switch cutout and pushes wall feet outward until they clear the piece's switches; it does not move keys. — The board is the search's output; the case adapts to it and reports what it cannot fix (`blocked`, `cap_hits`).
- 2026-10-22 — B14 stretch and derived effort measure 3D distance in the hand frame, not in-plane x, y. — In-plane distance let a 3D search hide stretch by lifting and curving columns; flat boards are unchanged.
- 2026-10-22 — 3D collision adds a finger access volume per key (cap top extruded 1 u along the normal, finger keys also swept 1.5 u toward the user at 45°); access vs access is allowed. — Solid-only tests passed keys buried under neighbours and thumbs raised into the index finger's path; access volumes facing each other are normal on curved boards.
- 2026-10-22 — The geometry search applies default `BuildLimits` to 3D candidates when the profile has no `[build]`. — Otherwise key angle and height are unbounded (vertical thumb clusters); flat candidates and profile hashes stay unchanged.
