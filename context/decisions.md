- 2026-10-21 — Tabu search keeps a Δ matrix of the *linear* (n-gram) part of every swap delta and adds the finger-load part (M02/M04, non-linear) fresh during each scan. After a move (r, s), pairs touching r or s are recomputed; the others get `Scorer::delta_shift`: Taillard's O(1) QAP update per pair channel plus the trigrams holding a symbol of each pair, found through a new per-symbol-pair trigram index built with the scorer. The matrix and score are rebuilt from scratch every 1000 iterations against f32 drift. — An iteration costs ~3× less than a full rescan with `delta`; exact (proptest) up to f32 rounding. `delta` itself is now `delta_linear + delta_load`, with no measurable speed change (`gecko perf` 1.80 µs before and after).
- 2026-10-21 — Tabu offers a layout to top-K only when the scan shows it is a local optimum (no improving swap), and polishes each restart's best with steepest descent. Tenure is drawn per move (Taillard redraws it periodically); "evals" counts every swap scanned, so tabu's evals/s is not comparable to SA's. — Otherwise top-K fills with one-swap neighbours of the same optimum.
- 2026-10-21 — B11 movement table = KLO `finger_switch_factor` seeds, KLO's finger-length direction rule (factor 2) and row² cost (offset 0.1), plus a lateral term (columns beyond finger spacing, factor 1, KLO ships 0) so it covers LSB. Ring pairs only are scaled by Häger-Ross coupling relative to the six-pair mean. — The KLO table already encodes the other pairs by hand; the independence data is the physical basis for the ring entries the issue asked for. Unbalancing factor left out (no per-key unbalancing in geometry yet, B13).
- 2026-10-21 — B11 in the default profile at 0.5 spread units, on top of B14 (not replacing it). — At 0.5 the reference order is unchanged and the optimum changes by ~0.1% of the objective; at 1 Halmak and Colemak swap places. The two metrics agree at the optimum; B11 adds finger-specific costs (ring coupling, KLO asymmetries) that B14's pure geometry lacks.

Bilateral-combination configs make same-hand rolls the risky case. A plain bigram table keeps the hot loop unchanged.

- 2026-10-21 — `gecko verify` refuses time-budget runs, stops before re-running if an input hash differs, and compares scores to 1e-9 relative (chars and evals exactly). — A time-budget re-run can't match by design, and a changed input already explains any mismatch. The tolerance allows last-bit float noise across builds. The re-run writes to a temp dir so the run directory stays as recorded.

- 2026-10-21 — Shift (D1, #4) is a fixed `⇧` key on the layout (may repeat, e.g. one per hand), not a corpus token; the corpus keeps case counts as two extra tables (`GKCORP3`: presses before y, presses between x and y; hold model, one press per run of shifted symbols). Costs go to M01 (Shift key effort per press) and Y01 (press, +same-finger extras) via two small own channels; the best `⇧` per shifted key is fixed at build time. No `⇧` = no cost, so existing layouts and scores are unchanged. — A `⇧` token in the n-gram stream would rewrite every letter bigram around capitals and count Shift as SFBs in B01; separate tables keep existing metrics comparable and delta exact.
- 2026-10-21 — Tokenizer folds US-QWERTY shifted characters onto their key when only the key is in the charset (`:` → shifted `;`, `"` → shifted `'`, …), so rebuilt default-charset corpora count `"`/`:`/`?` as keystrokes on their keys; with `--charset code` they stay their own symbols. `GKCORP3` is written only when shift counts exist, so the bundled corpora (no raw sources committed) keep their bytes and hashes; Shift is dormant on them until rebuilt.
- 2026-10-21 — KLE import guesses rows by aligning same-x columns (then y for loose keys), takes the last of ≥ 4 rows as thumbs, and assigns fingers by nearest home-row column with ties to the left; efforts come from ortho-30's table. Stretch keys are not `home` (ortho/ansi convention; corne/sweep mark them home). — Reproduces all four bundled boards and traditional ANSI fingering from geometry alone; KLE labels vary too much to trust. Imports write no thumb fills: which thumb gets space is a user choice.
- 2026-10-21 — Hand model (#6): Buchholz 1992 kinematic ratios × hand length for phalanges; active ROM (Becker & Thakor 1988) as hard limits, functional ROM (Bain 2015) as the low-cost zone; DIP–PIP as a soft per-finger coupling, not the "⅔" rule. Finger MCP positions come from a scan or geometry parameters, not Buchholz metacarpal ratios. — Phalanx ratios cross-check across two secondary sources; metacarpal ratios and the ⅔ rule could not be sourced, and measured DIP/PIP slopes (0.44–0.87) break down in fingertip-press postures.
- 2026-10-21 — Navbar (#82): inputs are top-level tabs in two toolbar tracks (Board · Hand · Corpus · Profile · Search | Optimize · Explore · Stats · Runs); the start layout, editor, pins and reference stay on Optimize's left panel rather than a tab of their own. — The layout is edited on the 3D view, so it belongs beside it; the issue's tab list has no Layout tab. Stored `gecko.view` values from the old shell map to the new tabs.
- 2026-10-21 — Extra neighbourhoods (same-finger column exchange, 3-cycle, depth-2 swaps) run only at a swap-local optimum inside the shared `steepest_descent`, configured once per run via `Params.moves` (copied onto `Ctx` by the runner), and are off by default. — One switch improves every local search (HC, SA polish, GA, BLS/explore) without touching the hot swap loop; the bench showed no gain for SA/BLS, so swap-only stays the default. Depth 2 tries second swaps only after the 32 least-worsening first swaps (full width is O(m⁴), 60× a swap descent on 30 keys); trial moves restore score/loads from a snapshot rather than subtracting deltas, so no drift.
- 2026-10-21 — Layer modes (hold, one-shot, toggle) are encoded in the layer-key token (`①` / `⓵` / `❶`), with TOML `mode` as a friendlier spelling that rewrites the token. — Flat strings (runs, `raw:`, WASM, web) stay self-describing with no new field; old runs and layouts are hold as before. One-shot/toggle layers lose only the layer key (the finger is free); a toggle layer's own key position is where it is left. Y01 counts the presses between two symbols per mode (toggle state = the first symbol's layer), and Y02 also flags pairs after a one-shot symbol.
- 2026-10-21 — `Geometry::flat2d` (L9): PCA plane per hand only when the halves' plane normals differ by > 5°, otherwise one plane for the board; in-plane axes are board x projected onto the plane (y completes it, pointing toward the user); each half keeps its 3D centroid's x, y. Overlap removal pushes pairs apart along the SAT MTV, signed from center to center, so keys never pass each other (row/column order kept) — no explicit order constraint needed. Served precomputed as `flat` on `/api/geometries` (mini keyboards render before WASM loads). — Keeps a split board's halves where they are and its rows horizontal; flat boards are untouched.
- 2026-10-21 — Asymmetric row costs (C3) are a profile table `row_offset` added to M01 effort, not new geometry efforts. Default/code: ring ∓0.1, middle ∓0.2, index ±0.2 (above/below home), pinky 0; zero when absent, and left out of `table_hash` then. — Works on every geometry and stays tunable/calibratable; values scaled from KLO's crkbd key costs (≈7.5 KLO units per effort unit). Reference ranking unchanged on ansi-30; M01 `scale` not re-normalized (shift is <2%).
- 2026-10-21 — Chat and non-English corpora for L05: cmini `reddit` (chat) and `french` (picked over `dutch`: larger user base, many accented letters to exercise folding). - 2026-10-21 — C4 metrics (#17) ship unweighted in every profile. — They report now and are ready for `gecko profile fit`/normalize; adding weights would shift the calibrated ranking and belongs to a deliberate re-tune.
- 2026-10-21 — M03 = √Σ share² and M07 = max share ÷ `finger_target`, both over non-thumb shares like M02; scored linearly in the reported value (so explore re-scoring needs no special case). — RSS needs no target (Kühlmak); M07 reuses the existing targets so "pinky especially" falls out of the low pinky target instead of a new profile field. M07 is a max (non-smooth) but exact in the delta since load terms are recomputed from the accumulators.
- 2026-10-21 — B07 = inward bigram rolls only (one ID, Max); B09 = pinky–ring pairs only; B06 uses finger length order pinky < index < ring < middle; S05 uses B14 stretch as KLO's "movement cost" (works on any geometry, unlike the E05 comfort table); T09 = sum of both B14 stretches when both steps stretch; T10 = both bigrams "bad" (SFB, LSB, full or half scissor). — Simplest readings of the catalog that need no new profile parameters; thumbs are excluded from the row/finger-pair metrics as in B05.
- 2026-10-21 — Layout import (Oxeylyzer/genkey/cmini) maps keys by physical position onto the 30 alpha keys and ignores source fingering (angle mod) with a warning; a letter outside those keys (thumb, extra column) is an error, other dropped symbols a warning. Silently dropping a letter would score a layout without it.
- 2026-10-21 — Y03 paired symbols: a sparse per-pair list weighted by open+close symbol frequency (not bigram frequency, since `(` and `)` are rarely typed back to back), cost 0 for adjacent/mirrored on one layer with the opener left / on the left hand, 50 reversed, 100 otherwise; "mirrored" = same row, finger and stretch flag (not exact column). `code` profile weight 0.5, scale 25 (one typical pair's share). — Keeps the delta to ≤ 4 entries; order matters for memorability but less than proximity; finger+row matching works on any geometry without a mirror map.
- 2026-10-21 — Word counts live in a side file `<corpus>.words.tsv`, not in the `.gkc`. — Keeps the corpus format and hashes (recorded in every run) unchanged; only word imports have word counts. - 2026-10-21 — No word list for `mt-450k` (or text-built `english`/`code`). — mt-450k weights all 450k words once, so a 20k cap would be an arbitrary alphabetical slice and the full list is ~5 MB; `english`'s source novels aren't in the repo. `analyze --words` errors clearly instead; `shai` and `mt-10k` cover the use case.
- 2026-10-21 — Worst words cover lower-is-better metrics only; costs are per occurrence (% tables ÷ 100, so SFB cost = number of SFBs), ranked by freq × cost; cross-word n-grams belong to no word. — "Worst" for a higher-is-better metric (rolls, alternation) has no per-word cost to blame; per-occurrence counts read naturally (`decided`: 4 SFBs on QWERTY). On a word corpus without `␣` the words' SFBs sum exactly to B01 (tested).
- 2026-10-21 — Thumb trigrams: T12 thumb roll / T13 thumb alternate (T09–T11 were already catalogued). Both `max`, unweighted by default. — Classes still partition all trigrams; the non-thumb step of e.g. `LM LI RT` is already scored by bigram metrics, so it does not split the class further.
- 2026-10-21 — M09 = thumb share %, cost `(share − thumb_target)² / 10` (same form as M04); `thumb_target` default 18 = Space alone on English. Not in `table_hash`: raw M09 doesn't depend on it, so atlases stay re-scorable. — A soft target, not a cap, lets profiles ask for a thumb letter (raise target) or keep thumbs to Space.
