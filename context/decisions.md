# Decisions

Newest last. Format: date — decision — why. Agents add entries for any non-obvious choice.

- 2026-10-20 — Rust core, CLI, server, WASM. — Speed in the hot loop; one scorer shared by CLI and browser.
- 2026-10-20 — TypeScript (not plain JS) for the web UI. — Types help agents work reliably with little supervision; the user is fine with TS for that reason.
- 2026-10-20 — React + react-three-fiber for the UI. — Widely known by agents; good Three.js integration.
- 2026-10-20 — Geometry / layout / corpus kept separate; positions always 3D. — 2D → 3D without rewriting the core.
- 2026-10-20 — Linear metrics folded into one table per n-gram order; delta evaluation for swaps. — Metric count doesn't slow search.
- 2026-10-20 — Start with the 30 main keys on a standard row-staggered board. — Requested; symbol layers come later.
- 2026-10-20 — Geometry phases: 2D (x, y, rotation) → z axis + hand model → free-form 3D curved with no key intersections. — Requested roadmap.
- 2026-10-20 — Development is autonomous. Agents make reasonable decisions without asking and record them here. — Requested by the user.
- 2026-10-20 — Web visual design adapted from the user's JAGUAR design doc into `context/design.md` (monochrome, one accent, semantic colors for state only, dense tool shell). — Requested; keeps both projects' tools consistent.
- 2026-10-20 — Profile weights apply to metric values in natural units (%, avg effort); direction comes from the metric so weights are always ≥ 0. Spread-normalization deferred. — Simple and readable; default weights tuned so the ranking test passes.
- 2026-10-20 — Frequencies normalized over the symbols on the layout. — Layouts with different punctuation stay comparable; matches common analyzers.
- 2026-10-20 — Trigrams stored sparsely per symbol with `trigram_coverage` = 0.99 (renormalized) in the profile. — ~2× faster deltas; scoring, deltas and reports use the same table so delta == full holds.
- 2026-10-20 — Own xoshiro256++ RNG instead of `rand`. — Identical streams on native and WASM, no dependency churn.
- 2026-10-20 — Metric tables grouped in `metrics/mod.rs` (+ `trigram.rs`) instead of one file per metric. — Most metrics are 1–3 lines; one file each would be noise. Split when a metric grows.
- 2026-10-20 — Optimizers boxed as `dyn Optimizer` per worker; dispatch is per step (≥ thousands of evals), never per evaluation. — Keeps the runner simple without touching the hot loop.
- 2026-10-20 — SA `steps = 0` means auto: about 4 restarts per worker within the budget. — Fixed 1M-step schedules never finished on short runs with many threads.
- 2026-10-20 — Bundled corpus: 10 public-domain Project Gutenberg novels (6.1M chars); compiled `data/corpora/english.gkc` is committed, raw text is not. — Works offline; reproduces published QWERTY SFB (6.63% vs ≈ 6.6%). Add chat/code corpora later.
- 2026-10-20 — SSE terminal events are `done` / `failed` (not `error`). — `error` collides with EventSource's built-in connection error event.
- 2026-10-20 — Web toolbar modeled on the Unity editor: icon view tabs (Home, Results, Layout analysis) left, Play / Pause / End centred, progress right; wordmark removed; Algorithm moved into Inputs › Search. — Requested by the user.
- 2026-10-20 — Transport active state uses `--accent` (Unity's blue play-mode tint) instead of ink. — The live run is "the one thing that needs attention"; keeps the one-accent rule.
- 2026-10-20 — Pause is real: `optimize::Control` (cancel + pause) replaces the bare cancel flag; workers sleep while paused and paused time is excluded from the time budget and `elapsed_ms`. — A UI-only pause would let the budget expire while paused. The deadline check only takes the pause lock once wall time passes the budget, so the hot loop is unchanged.
- 2026-10-20 — Community corpora imported from cmini's `words.json`, not its n-gram tables; skipgrams across word boundaries estimated by word independence. — cmini's tables have no cross-word n-grams, but GECKO's skipgrams span spaces; word counts make in-word counts exact and let us estimate the rest. QWERTY SFB matches the source tables exactly (shai 6.70 %).
- 2026-10-20 — Corpus format `GKCORP2` adds skip-2 and skip-3 tables (for decayed skipgram metrics); `GKCORP1` still loads with them zero. — Old files keep working; `english.gkc` rebuilt (scores unchanged).
- 2026-10-20 — Robustness report (L05) ranks layouts per corpus and sorts by mean rank, not by raw score spread. — Corpora differ in overall difficulty, so raw scores aren't comparable across them; ranks are.
- 2026-10-20 — Profiles carry `[sfb]` params (distance transform, lateral, finger factors, skip decay); metric tables are built per profile. — Same-finger cost shape is a modelling choice, not geometry. Defaults reproduce the old B03.
- 2026-10-20 — Far skipgrams (gaps 2–3) are a third pair channel (`fkf`/`ckf`) used by S02, not mixed into S01. — S01 stays comparable with other analyzers; the channel is compiled out when unused.
- 2026-10-20 — B14 ported from Oxeylyzer 2 (`cached_layout.rs` @52b271a), constants unchanged. — One stretch formula for every geometry; replaces hand-listed LSB/scissor flags in the default profile at their combined spread weight.
- 2026-10-20 — Comfort tables live in `data/comfort/`, named per metric by the geometry (`[comfort]`), and are serialized with it. — They are tied to key positions; serializing them keeps WASM == CLI without a new API.
- 2026-10-20 — E05 (measured Engram comfort) in the default profile at weight 1 (spread units). — Without it the optimum was last of all layouts on measured comfort; with it the optimizer gives up 0.2% of the rest of the objective and beats every reference layout on comfort.
- 2026-10-20 — Default profile in spread units (`[scale]` = stdev over the 10 reference layouts). — Weights become comparable; it showed SFB carries ~8× any other metric.
- 2026-10-20 — Ranking test no longer orders Colemak vs Dvorak; it pins modern < {Colemak-DH, Dvorak} < QWERTY. — With B14 and E05 the default profile puts Dvorak level with Colemak-DH (28.9 vs 29.2); the measured comfort data favours Dvorak's alternation. Revisit if this is judged wrong.
- 2026-10-20 — Explore hooks into the optimizers through an `Observer` trait object in `Ctx` (`optimum`, `edge`, `exclusions`), called only per descent/kick. — Keeps the dependency direction `explore → optimize`; the hot loop is untouched.
- 2026-10-20 — Atlas stores raw metric vectors per optimum; any profile with the same tables (`Profile::table_hash`) re-ranks it exactly. — "Archive once, re-weight forever" (research/search-space-visualization.md): weight edits never need a new search.
- 2026-10-20 — Mirror canonicalization only when mirrored scores are provably equal and nothing is pinned. — Otherwise mirrored layouts are genuinely different optima; the default ansi profile is not symmetric.
- 2026-10-20 — Exclusion restarts start next to a known good layout and walk out to distance ≥ d, then descend under the Hamming constraint (flagged `CONSTRAINED`). — Random starts rarely land in the band "good but different"; this finds distinct near-best layouts (d = 8, 12).
- 2026-10-20 — BLS stagnation 150 kicks (not 400). — More restarts gave more distinct optima per second with the same best score in 20 s runs.
- 2026-10-20 — Families by leader clustering (radius in slots), not agglomerative clustering. — Linear in the focus size, deterministic, and the radius is meaningful to a user ("≤ 8 keys differ").
- 2026-10-20 — Atlas statistics run in WASM (`AtlasView`), not on the server. — Re-weighting, brushing and re-ranking 10⁴–10⁵ optima must be instant; the binary files load directly.
- 2026-10-20 — The PCA map is fit on ≤ 3000 strided rows and does not depend on weights. — Points keep their place while weights change; only colour and rank move.
- 2026-10-20 — Card grids use `grid-template-columns: minmax(0, 1fr)`. — An `auto` track grew to the canvas's initial 600px width and the size observer then kept it there (charts overflowed their cards).
